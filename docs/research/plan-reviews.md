# Technical correctness and consistency

VERDICT: Most of the versions, APIs and measured numbers in PLAN.md match the research, and the plan already includes the main fact-check corrections: av==16.1.0, INT8 working again on ctranslate2 4.7+, keepNames, the compileAsync gaps, parse() throwing, fallbacks being beta-only, and the sampler budget. I checked the three r186 source: textures with the same UUID share one binding, so a single packed ORM texture costs one sampler. The WebGL2 fallback is covered apart from ClusteredLighting, which should be cut. The defects sit where subsystems meet. The timing between the loudness band, the P2P audio and the transcripts breaks the 1:1 rule and the Listener's hearing in ways the gates may not catch. The quick tunnel's restart and per-origin behaviour undercuts the resume and persistence claims. Several runtime traps need one-line rules written into the P0 contracts and CLAUDE.md before P1 starts: Ctrl+W crouch, type-only imports under Node type stripping (reproduced locally), the structured-output error paths, and the TypeSafe SDK defaults.

## Issues
- [HIGH] §3.1, §4.5, §4.6: The 1:1 voice gating can't work as specified.
- **Onsets get muted.** The speaker's band reaches listeners only via pose packet → server → snapshot. That takes about 120-300 ms, and 400+ ms in the tunnel jitter windows measured earlier. The P2P audio arrives in about 50-150 ms. With silent = 0 m, the first syllable of every utterance and every radio key-up is faded out for everyone.
- **Whispers can vanish.** A whisper that the gate calls 'silent' is muted for teammates.
- **Alt-tab freezes the band.** Pose packets sent from the render loop stop when a friend alt-tabs.
- **Nobody computes the client distance.** §3.1 says the server computes path distance, but §4.6 has each client compare a path distance it has no defined way to compute.
- **The metric is lopsided.** The prototype soundFlood is 4-neighbour Manhattan, so 'talk 10 m' reaches only about 7 m diagonally.
- **The self-healing fallback ignores gating.** A plain <audio> element bypasses gating, so that voice is heard map-wide.
  FIX: In §4.6, §4.5 and constants.ts:
- (a) Send band and radio-PTT over a negotiated unreliable RTCDataChannel on each existing peer connection, so it arrives with the audio. Send them to the server as events from the worklet port, not from rAF.
- (b) On the receiving client, treat 'silent' as 'hold the last non-silent radius for 1.5 s'. Never gate below the whisper radius while the receiver's analyser shows energy. Give the detector 2-3 dB hysteresis and a 200 ms hold, and set the gate threshold from the calibrated whisper level.
- (c) The server sends each client a uint8 path distance per speaker in every snapshot, computed with the same shared function the monsters use. The client gates on d ≤ R(band): distance comes from the server, loudness from the peer.
- (d) Make that function octile (√2 diagonals), or Euclidean within the same space or with line of sight.
- (e) The self-heal <audio> fallback drives element.volume from the same gain.

# Player experience and fun for a first-time friend group (2-6 players, Discord habits, mid-range PCs, some on speakers)

VERDICT: The core loop and the Listener hook follow the friendslop formula: a quota run, proximity voice, funny instant deaths and an HR roast. Every requirement in the brief is covered on paper, but three are weak in practice: sneaking (hiding and monster sight are never defined), AI (players can't see what the Listener understood, so it will read as random) and proximity voice (nothing gets friends out of Discord). As specced, the first night risks being confusing and quiet: Ctrl-crouch closes tabs, the first contract throws three instant-kill monsters at first-timers with no tutorial, and two monsters that punish voice will silence the crew. Almost every fix is a balance.json change, rules text or small UI (Risk-1 roster with a dormant Listener, death card and intercept log, a Hound noise threshold, adaptive calibration, creator inside the van, a sealed van and retreat after a kill). These belong in the P0 contracts so that G2 is fun, not just functional.
