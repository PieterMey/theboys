# voice

## Executive summary
Use a WebRTC full mesh: audio only, one RTCPeerConnection per pair of players, signaled over the game's existing WebSocket with MDN's perfect-negotiation pattern. For 4 to 8 voice-only players this costs about 55 kbps per stream on the wire (about 0.4 Mbps up and down at 8 players). It also means no media server runs on the home PC, which can't take inbound UDP through a Cloudflare Tunnel or Tailscale Funnel anyway (Funnel is TLS/TCP only, on ports 443/8443/10000). Use Cloudflare Realtime TURN as the relay. It gives 1,000 GB/month free (shared with the Cloudflare SFU), then $0.05/GB. The host server gets short-lived credentials from one REST call (TTL up to 48 h), and TURN over TLS on port 443 gets through strict firewalls. By comparison, Metered's free plan is only 500 MB/month, and self-hosting coturn behind a home NAT in Docker Desktop isn't worth it tonight. The old Chrome bug is still open (issues.chromium.org/40094084: status Assigned, P2, last modified 2026-06-11). A remote WebRTC stream passed to createMediaStreamSource stays silent unless a media element also uses it. So every remote stream must also go to a muted, playing <audio> element, kept in a Map so it isn't garbage-collected. Use muted, not volume=0. Firefox doesn't need this, but it does no harm there. Echo is much less of a problem than it used to be. Chromium main enables Chrome-wide echo cancellation by default on Windows, Mac and Linux; it mixes and cancels all of Chrome's audio going to the output device, Web Audio included (the old AEC-with-Web-Audio bug, 687574, is marked Fixed). Firefox uses its own graph's mixed output as the echo reference. Edge has one unconfirmed report of echo leaking (Aug 2026), and the 'remote-only' mode would miss Web Audio playback, so request echoCancellation:true and still ask everyone to wear headphones (HRTF positioning needs them anyway). For position, use PannerNode with HRTF and distanceModel 'linear', the only model that reaches true silence at maxDistance. Muffle voices behind walls with a lowpass filter plus gain driven by grid line-of-sight. Add one shared ConvolverNode reverb send using generated impulse responses, and a separate radio chain for walkie-talkies. One AudioWorklet mic tap drives voice detection (monster 'noise' events at up to 10 Hz) and a ring buffer that keeps the last few seconds for opt-in mimic clips; this works better than MediaRecorder. WebCodecs Opus now runs in all desktop browsers (Chrome/Edge 94+, Firefox 130+, Safari 26), so relaying Opus over the WebSocket is a workable fallback for a later phase. LiveKit Cloud's free Build plan is the backup SFU: 5,000 participant-minutes/month hard cap, and its SDK already has webAudioMix and setWebAudioPlugins. Recommendation for tonight: ship the mesh with Cloudflare TURN, the muted-element Web Audio graph, voice-detection noise events, and the radio and dead-player channels. Gate them with a Playwright test that uses a fake mic. Leave the WebSocket/WebCodecs relay and the mimic recorder for after the core loop works. Note: the web search budget ran out late in this research, so the newest relay-percentage data and Edge's echo-cancellation status could not be checked further.

## Recommendations
- [TONIGHT] Topology: WebRTC full mesh, audio-only, one RTCPeerConnection per player pair, signaled over the existing game WebSocket using MDN perfect negotiation (polite = lexicographically smaller playerId). Cap lobbies at 8. -- Voice-only mesh is cheap (~55 kbps/stream incl. RTP/UDP/SRTP overhead). The browser provides jitter buffer, PLC and Opus in-band FEC for free. Per-peer RTCRtpSenders make dead/alive gating trivial. Nothing media-related has to accept inbound connections on the home PC.
- [TONIGHT] Relay: Cloudflare Realtime TURN only. The host's Node server calls POST https://rtc.live.cloudflare.com/v1/turn/keys/{KEY_ID}/credentials/generate-ice-servers ({ttl:14400}) for every join, drops any :53 URLs, and sends iceServers to the client over the WS. Clients call pc.restartIce() when connectionState becomes 'failed'. -- 1,000 GB/month free, shared with the SFU, then $0.05/GB. Anycast, with UDP/TCP/TLS transports on 3478/80/443/5349 for firewalls. Roughly 10-25% of sessions are commonly cited as needing relay, so with 6+ player pairs at least one relayed link per night is likely. Metered free (500 MB/month) and coturn behind home NAT are worse options.
- [TONIGHT] Rendering: a single game AudioContext, created or resumed in the 'Join' click handler. Per remote peer: muted, playing <audio> keep-alive -> MediaStreamSource -> BiquadFilter lowpass + Gain (occlusion) -> PannerNode {panningModel:'HRTF', distanceModel:'linear', refDistance:1.5, maxDistance:20-25, rolloffFactor:1} -> per-voice Gain (alive/dead gating, user volume) -> voice bus -> DynamicsCompressor -> destination. Also a reverb send into a shared ConvolverNode, and a 2D radio branch. -- Chrome bug 40094084 is still open; without the keep-alive element Web Audio receives silence. Linear is the only spec distance model that reaches gain 0 at maxDistance, because rolloff is clamped to [0,1]. The default 'inverse' model leaves a voice 20 m away at about -26 dB, which is still audible across the map.
- [TONIGHT] Capture: getUserMedia({audio:{echoCancellation:true, noiseSuppression:true, autoGainControl:true, channelCount:1}}). Tell all players to use headphones. Offer an optional 'I'm on headphones' toggle that re-acquires the mic with echoCancellation:false for cleaner voice. Never request 'remote-only'. -- In Chrome desktop, echoCancellation:true selects Chrome-wide AEC, which cancels everything Chrome plays to the output device, including Web Audio. 'remote-only' selects the PeerConnection-only canceller. Edge has one unconfirmed report of echo leaking. Firefox cancels only its own graph's output. HRTF needs headphones, and headphones also avoid AEC double-talk clipping during loud jump-scares.
- [TONIGHT] VAD and monster hearing: an AudioWorklet 'mic-tap' on the local processed mic posts RMS at about 50 Hz. A hysteresis gate (open -45 dBFS, close -52 dBFS, 250 ms hangover) sends WS {t:'voice', db, radio} at up to 10 Hz while open. The server maps dB to a noise radius (about 4-18 m) at the speaker. For radio transmissions it also adds a noise event at each receiving walkie. -- AudioWorklet keeps running when the tab is in the background, where rAF-polled AnalyserNodes stop. The same worklet supplies the mimic ring buffer. Voice detection runs on the post-AEC track, so game sounds leaking from speakers are mostly removed before they can trigger monsters.
- [TONIGHT] Voice channels: (1) proximity is open mic through the gate, with optional push-to-talk via micTrack.enabled. (2) Radio needs a walkie item: hold a key, WS {t:'radio',on}, and receivers holding radios open that speaker's 2D radio chain (bandpass + waveshaper + compressor + hiss) with 100 ms squelch bursts on key down and up. (3) Dead players hear dead players (2D, slightly reverbed) plus the area around the player they spectate. Alive players never hear the dead: the dead player's client calls sender.replaceTrack(null) for each alive peer, and the receiver sets gain 0. -- Copies the Phasmophobia/Lethal Company mechanics that force teamwork: a split team must use radios, and talking attracts monsters. A mesh makes this per-listener gating private and cheap.
- [TONIGHT] Automated voice test with Playwright (npm): launch the installed Chrome (channel:'chrome') with --use-fake-ui-for-media-stream --use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<abs>/voice.wav%noloop --autoplay-policy=no-user-gesture-required, in 2-4 pages. Assert that getStats inbound-rtp audio bytesReceived increases and that receiver analyser RMS is above 0.01. Add one control test without the keep-alive element to detect whether 40094084 ever gets fixed. For Firefox, use prefs media.navigator.streams.fake=true and media.navigator.permission.disabled=true. -- No human tester is available before tonight. Agents can verify the whole pipeline headlessly and catch silent-voice regressions.
- [TONIGHT] Self-healing check: if a peer's WS voice detection says 'talking' and inbound bytesReceived grows, but that peer's analyser stays below 1e-4 RMS for 3 s, switch that peer to an unmuted plain <audio> element (no spatial audio) and log it. -- Cheap insurance against the Chrome bug's reported 'stops working after some time' variant and against GC'd nodes.
- [later] Mimic monster clips: an opt-in checkbox in character creation, default OFF, with clear text. Capture on the speaker's own client from the mic-tap ring buffer: speech segments of 0.8-3.5 s with 250 ms pre-roll, Int16 mono 24 kHz. Send them as WS binary to the host, which keeps them in memory only (up to 12 clips per player), wipes them at session end, and never sends them to the LLM. Replay with AudioBufferSourceNode (playbackRate 0.94-0.98) through the exact same voice chain at the monster's position, sometimes over the radio. -- An AudioWorklet ring buffer gives pre-roll and exact clip boundaries. MediaRecorder has no pre-roll, and its timeslice chunks after the first can't be decoded on their own. Recording remote streams on receivers would also hit the Chrome silent-stream bug, which covers MediaRecorder too. Using the same chain makes the mimic sound exactly like a teammate. Estimated at about 150 lines, so it's the first feature after the MVP.
- [later] Later fallback: relay Opus over the game WebSocket using WebCodecs, only for pairs whose ICE fails even with TURN. -- AudioEncoder/AudioDecoder ship in Chrome/Edge 94+, Firefox 130+ (desktop) and Safari 26. Capture has to use an AudioWorklet because Firefox lacks MediaStreamTrackProcessor. It needs a hand-written jitter buffer and adds TCP head-of-line stalls, so it's too much for tonight.
- [later] Backup SFU if the mesh or TURN proves flaky: LiveKit Cloud Build (free) with livekit-client 2.22.3, using new Room({webAudioMix:{audioContext:ctx}}) plus RemoteAudioTrack.setWebAudioPlugins([lowpass, occlGain, panner]), and server tokens from livekit-server-sdk 2.19.1 AccessToken. -- Free tier: 5,000 participant-minutes/month (hard cap), 100 concurrent, 50 GB downstream, with embedded TURN/TLS. The SDK already mutes the element and routes through Web Audio. That's about 7 four-player, 3-hour sessions a month before the cap.
- [TONIGHT] Avoid tonight: simple-peer (last release 9.11.1 in 2022), ScriptProcessorNode, the PeerJS public cloud broker, a self-hosted SFU or coturn on the home PC, one ConvolverNode per voice, new AudioContext({sampleRate}), createMediaStreamTrackSource (Firefox-only), and routing the local mic to destination. -- Each is unmaintained, deprecated, needs inbound UDP/port forwarding, costs extra CPU, or breaks in some browser.
- [TONIGHT] Tools and accounts to ask the user for: create a free Cloudflare account and a Realtime TURN key in the dashboard (Realtime > TURN Server > Create), and put CF_TURN_KEY_ID and CF_TURN_API_TOKEN in the server-only .env. No MCP is needed for voice; plain Playwright covers testing, and a Playwright MCP is optional. -- Creating the TURN key is a two-minute dashboard step that agents can't do without an account. The keys must never reach the client.

## Risks
- Remote voices are silent in Chrome or Edge (bug 40094084), or the keep-alive element gets garbage-collected or paused, so voices go silent mid-session. => Use the keep-alive muted <audio> plus strong references in a Map, a Playwright regression test, and the runtime self-healing check: if a peer is talking per WS but silent in the analyser for 3 s, fall back to a plain unmuted <audio> for that peer.
- Echo or feedback when a player uses speakers, especially on Edge (Chrome-wide AEC not confirmed there) or Firefox with audio from other tabs. AEC double-talk can also chop voices during loud scares. => Show 'headphones strongly recommended' in the lobby and on the character-creation mic test. Use echoCancellation:true by default and never 'remote-only'. Recommend Chrome. Offer a 'headphones mode' that turns AEC off for cleaner audio.
- ICE fails for a pair (symmetric NAT or CGNAT, Starlink, corporate or campus networks) when the TURN key isn't set up. => Create the Cloudflare TURN key before tonight, and include turns:443?transport=tcp. Show per-peer status (direct/relay/failed) in the lobby so problems surface before the round. Call restartIce() on failure. Temporary fallback: Metered free TURN (500 MB/month).
- Free-tier hard caps if switching to LiveKit Cloud (5,000 participant-minutes/month): new connections fail once the cap is reached. => Keep the mesh as the primary path. If LiveKit is used, check usage in the dashboard. A 4-player, 3-hour session uses about 720 minutes.
- CPU load on mid-range PCs from HRTF panners, convolvers and the WebGPU renderer together. => Use HRTF only for voices (8 or fewer), equalpower for SFX, and 1-3 shared ConvolverNodes instead of one per voice. Update positions at frame rate but filters only at 10-20 Hz.
- Background tab or alt-tab: rAF stops, so panner and listener positions freeze and rAF-polled voice detection stops. => Run voice detection and level metering in an AudioWorklet. Keep network position updates on a timer or WS-driven loop. Accept frozen spatial positions while the tab is hidden.
- Privacy and consent problems from the mimic voice recordings. => Make it opt-in and off by default, with a visible indicator. Keep clips in host memory only, wipe them at session end, never write them to disk, and never send voice to Claude or JEV.
- Mesh scaling beyond 8 players (N-1 encodes and uploads per client, N(N-1)/2 ICE connections). => Cap lobbies at 8. For bigger groups, move to LiveKit Cloud or Cloudflare Realtime SFU later.
- Chrome's AGC adjusting the Windows mic slider annoys players, or AGC breaks fixed voice-detection thresholds. => Calibrate the voice-detection threshold in the mic test. Offer an autoGainControl toggle with a manual mic-gain slider.
- Not enough time tonight for the WebCodecs relay or the mimic recorder. => Leave both out of the MVP. Ship the mesh, TURN, the Web Audio graph, voice detection, and radio/dead channels first, gated by the Playwright test.

## Decision-critical claims
- Chromium issue 40094084 (remote RTC MediaStream is silent in Web Audio unless attached to a media element) is still open as of its 2026-06-11 modification, so the muted keep-alive <audio> workaround is mandatory in Chrome 154 and Edge.
- Chrome desktop (Win/Mac/Linux) enables Chrome-wide echo cancellation by default, and with echoCancellation:true it cancels all Chrome playback to the output device, including Web Audio-rendered remote voices. If this is wrong, players on speakers will echo and headphones become mandatory.
- echoCancellation:'remote-only' maps to the PeerConnection-only canceller in Chromium and should not be used when voices are rendered through Web Audio.
- Cloudflare Realtime TURN gives 1,000 GB/month free (shared with the SFU), then $0.05/GB, with REST-minted credentials (TTL up to 48 h). This makes TURN effectively free for this game.
- The home PC cannot host UDP media through Tailscale Funnel or Cloudflare Tunnel (TLS/TCP only), so media must be P2P/TURN or a cloud SFU rather than a self-hosted SFU tonight.
- A voice-only WebRTC mesh is practical for up to about 8 players (~55 kbps per stream).
- LiveKit Cloud's free Build plan is capped at 5,000 participant-minutes/month as a hard limit, enough for about 7 four-player, 3-hour sessions.
- WebCodecs Opus AudioEncoder/AudioDecoder is available in Chrome/Edge 94+, Firefox 130+ (desktop) and Safari 26, so a WebSocket audio relay fallback is possible in every desktop browser (capture via AudioWorklet).

## Open questions
- Will the user create a Cloudflare account and Realtime TURN key (or a LiveKit Cloud project) before tonight? The server needs CF_TURN_KEY_ID and CF_TURN_API_TOKEN in the server-only .env.
- What is the maximum lobby size: 4 (Phasmophobia/Lethal Company), 6 (R.E.P.O.) or 8? Above 8, an SFU is needed instead of the mesh.
- Which browsers will the friends use, and do they all have headphones? Edge's Chrome-wide AEC status is unverified (one Aug-2026 report of leakage).
- Should the mimic voice feature be opt-in (recommended) or opt-out among friends, and is it wanted in the MVP at all?
- Does the user want speech recognition for ghost interactions (Phasmophobia-style 'spirit box' questions answered by Claude)? This needs separate research on Web Speech API or on-device STT availability in Chrome 154; the search budget ran out before it could be checked.
- Should IP privacy matter (P2P exposes public IPs between friends)? If so, use iceTransportPolicy:'relay' at the cost of TURN traffic.
- Not checked because the web search budget ran out: any 2025-2026 measurements of TURN-relay share, and whether Microsoft overrides Chromium's Chrome-wide AEC default in Edge. A follow-up run could verify these.
