# engines-native

## Executive summary
For tonight, the browser path (Three.js r186 WebGPURenderer, a Node 24 host behind an HTTPS tunnel, WebRTC + Web Audio proximity voice, and Claude called only from the server) is the only option that covers invite-by-link, proximity voice, LLM features and agent testability within a few hours. Native engines have a higher graphics ceiling but cost more in setup, distribution and testing. Godot 4.7.2 (stable since 2026-08-18; 4.8 reached feature freeze with dev7 on 2026-10-01) is the most agent-friendly native engine. Its Forward+ renderer is strong (SDFGI/VoxelGI, froxel volumetric fog, SSAO/SSIL/SSR, TAA/FSR2, and new in 4.7: AreaLight3D and HDR output), its .tscn/.gd files are plain text, and it has a full headless CLI. But Godot's web export is still WebGL2 'Compatibility' only, with no volumetric fog, SSR, SSIL, TAA or GI, so Godot in the browser looks worse than Three.js WebGPU. A third-party Godot WebGPU fork exists, but it is beta and lists Windows support as TODO. Native Godot plus GodotSteam 4.23 (2026-10-05, Steamworks SDK 1.65) gives Steam overlay invites, NAT-proof Valve relay (SDR) and Steam Voice, which can be fed into AudioStreamPlayer3D for proximity chat. On test app ID 480 that path has catches: you show up as 'Spacewar', lobbies are shared with junk and the lobby list had outages, friends must download and run an unsigned exe past SmartScreen or Smart App Control, and agents cannot test Steam P2P end-to-end on one PC with one account. Unity 6.6 (6000.6.4f1) now ships production WebGPU web builds, a beta Unity CLI with `unity license activate personal`, an official Claude Code plugin, and turnkey Vivox positional voice. Against that: Vivox's web SDK has no positional channels, the editor is a 3.85 GB download / 9 GB install that needs a Unity ID sign-in, and imports and IL2CPP builds are slow, so it is a day-plus effort. Unreal 5.8 has the highest ceiling (Lumen and Lumen Lite, MegaLights now production-ready, Nanite) and an experimental MCP plugin. It is still unrealistic for agents tonight: about 39 GB download / 70 GB installed, Blueprints are binary .uasset files, compile and cook cycles are long, an empty project ships at about 321 MB, and EOS voice has no positional audio. Three.js r186 already provides SSGI, GTAO, SSR, TRAA/TAAU, clustered lights, CSM and VolumeNodeMaterial volumetrics, and falls back to WebGL2 automatically. WebGPU is on by default in Chrome/Edge 113+, Firefox 141+ on Windows and Safari 26. For a dark, flashlight-lit procedural interior, the visual gap to native is smaller than the gap in distribution friction. RECOMMENDATION: (a) Tonight, ship the browser build with a server-authoritative Node 'game brain' (seeded procgen, monster AI, tasks, Claude director) and thin renderer clients, tested with Playwright multi-client runs using fake mics. (b) For v2, keep that server and, if the friends want a real fidelity jump plus Steam-native invites and voice, port the client to Godot 4.8 Forward+ with GodotSteam on your own Steam App ID ($100, Steam Playtest), keeping the web client as the zero-install option. Skip Unity and Unreal unless a human joins to do editor work.

## Risks
- Browser voice: WebRTC peer connections fail for friends behind symmetric NAT or CGNAT, and the tunnel carries only HTTP/WebSocket, not RTP. => Ship a server-relayed fallback: Opus frames from MediaRecorder or WebCodecs AudioEncoder sent over the existing WebSocket and played through the same PannerNode graph (4-6 players at about 32 kbps each is trivial). Or run coturn in Docker with a UDP port forward. Detect ICE failure at 5 s and switch automatically.
- A friend's browser or GPU lacks WebGPU or is weak (Firefox on Linux, old drivers, laptop iGPU). => three's WebGPURenderer falls back to WebGL2 by itself. Provide Low/Med/High presets (Low: no SSGI or volumetrics, GTAO at half resolution, DPR 1). Add an FPS auto-downgrade and test with forceWebGL:true in Playwright.
- Graphics expectations: the user asked for 'the most advanced graphics', and the web build's ceiling is below Unreal and HDRP. => Spend effort where horror reads: volumetric flashlight cones, GTAO/SSGI, TRAA, film grain, emissive and bloom, PBR assets (KTX2-compressed glTF). Record the native Godot 4.8 or Unreal option as the v2 fidelity path.
- If the native Godot + Steam 480 route is chosen anyway: shared junk lobbies, a lobby-list outage like Nov 2025, 'Playing Spacewar' presence, invites that only work when the build is already running, SmartScreen or Smart App Control blocking the unsigned exe, and Steam required on every PC. => Use FRIENDS_ONLY lobbies and filter on a unique lobby data key. Tell friends to launch the exe first, then accept the overlay invite. Keep an ENet + Tailscale fallback build. For v2, buy an own App ID and use Playtest.
- Agents cannot test Steam P2P, lobbies or voice end-to-end on one PC with one Steam account. => Abstract transport behind MultiplayerPeer and run automated multi-instance tests over ENet on localhost. Keep Steam for production only, and hold a short human smoke test with one friend before the session.
- Unity and Unreal setup eats the evening: multi-GB installs, sign-in or license steps, slow imports, shader compiles and cooks, binary assets agents cannot diff. => Do not use them tonight. Re-evaluate only if a human editor operator joins. If Unity: use the Unity CLI beta plus the official Claude plugin, and code-built scenes only.
- API key leakage, for example the key ending up in a client bundle, exported game or static file server, or .env being served. => Call Claude only from the host Node process using environment variables. Never import keys into client code or Godot exports. Serve only the built dist/ folder, and add a CI grep for 'sk-ant' and 'apikey_' in the client bundle.
- LLM latency or outage stalls gameplay. => Never block the game loop. Pre-generate between rounds, use a fast model with streaming for in-round barks, cache system prompts, and keep a deterministic fallback for every LLM-driven feature.
- Version churn: Godot 4.8 is in feature freeze, and the Unity CLI and Pipeline package are beta or experimental, so APIs may shift. => Pin exact versions (Godot 4.7.2 + GodotSteam 4.23, three@0.186.1) and upgrade deliberately after the session.

## Decision-critical claims
- Godot 4.7.x web export is Compatibility/WebGL2 only (no Forward+, volumetric fog, SSR, SSIL, TAA, SDFGI or VoxelGI), so a Godot web build cannot deliver advanced graphics; the only WebGPU option is an unofficial beta fork without Windows support.
- WebGPU is on by default for the likely friend browsers (Chrome/Edge 113+, Firefox 141+ on Windows, Safari 26), and Three.js r186 WebGPURenderer falls back to WebGL2 automatically.
- Three.js r186 ships production TSL nodes for SSGI, GTAO, SSR, TRAA, TAAU and volumetric lighting (VolumeNodeMaterial), which makes the browser's graphics ceiling good enough for horror interiors.
- With Steam app ID 480: lobbies work but are shared and have been flaky; presence shows 'Spacewar'; accepting an invite when the build is not already running launches Spacewar (inferred, medium confidence); Steam P2P cannot be tested on one PC with one account (medium confidence).
- Friends running an unsigned native exe will hit SmartScreen and possibly Smart App Control (no per-app exception), and code signing is not available tonight (Azure Artifact Signing: US/Canada individuals or EU/UK organisations only, after validation).
- Vivox (Unity) positional voice is unavailable in web builds, and EOS voice (Unreal) has no positional audio, so neither engine's turnkey voice solves proximity chat in a browser.
- Unity Personal still requires a Unity ID sign-in (Hub, or the beta 'unity auth login' plus 'unity license activate personal'), and the editor is a 3.85 GB download / 9 GB install before modules.
- GodotSteam 4.23 (2026-10-05) supports stock Godot 4.4+ through a precompiled GDExtension zip that includes SteamMultiplayerPeer, so the v2 Godot path needs no custom engine build.

## Open questions
- How many players tonight (4 vs 6-8)? This decides whether a WebRTC voice mesh is enough or a server relay/SFU is needed.
- Which browsers, GPUs and OS do the friends use? Anyone on Linux/Firefox, Safari, or a laptop iGPU?
- Are any friends behind CGNAT or a strict corporate/university NAT? That decides whether TURN or server-relayed voice is mandatory.
- Do all friends have Steam accounts and are they Steam friends with the host? This only matters for the native or Steam v2 path.
- For v2, is the user willing to pay $100 for an own Steam App ID and complete Valve's tax, bank and identity verification? It is needed for proper invites and Playtest without the Spacewar problems.
- Will a human ever do editor work? If yes, Unity 6.6 (Vivox, URP + WebGPU) or Unreal 5.8 become more viable for v2.
- Which country is the user in? It affects code-signing eligibility (Azure Artifact Signing excludes EU individuals).
- Not verified live because the shared web-search budget ran out: the Windows Firewall prompt behaviour, Spacewar launch-on-invite, the Steam same-account P2P limit, steamworks.js lobby and networking coverage, and UE compile and cook times. The user can send a follow-up to continue searching.
