- Multiplayer and voice test pattern: one chromium.launch() per player, because the fake-audio file is per process (e.g. 220/330/440/550 Hz tones). Each player opens http://localhost:PORT/?room=TEST&name=pN&seed=1234&test=1. Wait for window.__game.ready, teleport players with window.__game.debug.teleport(id,x,y,z), then on each listener read window.__voiceDebug.levels (RMS and dominant Hz per remote peer). Assert that loudness drops with distance, the far player is silent, and walls muffle. Write PNGs and report.json under artifacts/<run>/ and have agents Read them.
- Voice implementation detail (verified on Chrome 154): for every remote track do const el = new Audio(); el.srcObject = stream; el.muted = true; el.play(); BEFORE ctx.createMediaStreamSource(stream) -> PannerNode('HRTF', distanceModel 'inverse' or 'exponential') -> destination. Without the muted element the WebAudio graph receives silence.
- The game must expose a test API on ?test=1: window.__game = { ready, state(), seed, players(), debug: { teleport, setInput({forward,sprint,crouch}), stepFrames(n), freezeAI(bool), setCamera(name) } } and window.__perf = { fps, frameMsP95, gpuMs (WebGPU timestamp-query via WebGPURenderer trackTimestamp), drawCalls }. Bypass pointer lock in test mode. This makes every tool (Playwright scripts, DevTools MCP evaluate_script, Playwright CLI eval) agent-drivable on a canvas, where accessibility snapshots show nothing.
