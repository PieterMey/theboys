# engines-native details

## Implementation notes
- MATRIX - graphics ceiling. Browser (Three r186 WebGPU): HIGH, with SSGI, GTAO, SSR+denoise, TRAA/TAAU, clustered lights, CSM/VSM, contact shadows, VolumeNodeMaterial volumetrics and height fog, but no hardware RT and per-draw CPU cost in JS. Godot 4.7 Forward+ native: HIGH+, with SDFGI/VoxelGI/LightmapGI, froxel volumetric fog, SSAO/SSIL/SSR, TAA/FSR2, AreaLight3D and HDR output. Godot web: LOW-MED (WebGL2 Compatibility). Unity: VERY HIGH native (HDRP); MED-HIGH on web (URP + WebGPU). Unreal 5.8: HIGHEST (Lumen/Lumen Lite, MegaLights, Nanite, VSM, Substrate).
- MATRIX - time to first playable with agents. Browser: about 2-4 h. Godot native + GodotSteam: about 4-6 h, plus Steam integration risk and no single-PC Steam test. Godot web: about 4-5 h. Unity: 1-2 days (install, sign-in, imports, IL2CPP builds). Unreal: 3+ days (39 GB download / 70 GB install, VS 2022 C++, shader compile, cook). These are estimates, not measured.
- MATRIX - invite UX. Browser: friend clicks an HTTPS link, picks name and avatar, grants mic permission. Godot + Steam 480: friend downloads a zip (about 38 MB exe compressed plus assets plus steam_api64.dll), clicks through SmartScreen, keeps Steam running, launches the build first, then accepts the overlay invite; presence shows 'Spacewar'. Unity: download plus Relay join code. Unreal: 0.3-2 GB download plus Steam or EOS session.
- MATRIX - proximity voice. Browser: medium effort (getUserMedia, RTCPeerConnection mesh, PannerNode panningModel 'HRTF' with distanceModel 'inverse', BiquadFilter low-pass for occlusion); TURN or server-relayed audio needed for symmetric NAT/CGNAT; Opus at 48 kHz sounds good. Godot + Steam: medium effort (Steam Voice into AudioStreamPlayer3D); SDR removes NAT problems. Godot web: high effort (JS bridge; AudioEffects unsupported). Unity: low effort natively (Vivox positional) but no positional voice on web. Unreal: medium (VOIPTalker attenuation over Steam OSS); EOS voice has no 3D.
- MATRIX - LLM integration. Browser/Node: easiest; @anthropic-ai/sdk 0.131.0 on the server, key read from host env only. Godot: the host instance's HTTPRequest/HTTPClient (SSE needs manual polling) or a Node sidecar; never in client builds. Unity: UnityWebRequest on the host. Unreal: FHttpModule (C++). Every option must keep keys host-side.
- MATRIX - agent-friendliness and testability. Browser: 5/5 (all text, Vite HMR, Playwright 4-client with fake mics, screenshots). Godot: 4/5 (text .tscn/.gd, headless import and export, Movie Maker PNGs; Steam P2P needs 2 accounts or 2 PCs, so use ENet localhost for tests). Godot web: 4/5. Unity: 2-3/5 (YAML plus GUID .meta files, slow domain reloads; improved by the Unity CLI beta and the official Claude plugin). Unreal: 1-2/5 (binary .uasset, long cooks, experimental MCP).
- MATRIX - risk tonight. Browser: MEDIUM (NAT/TURN, friends' GPU and browser variance). Godot native + Steam: MEDIUM-HIGH. Godot web: MEDIUM (low visual payoff). Unity: HIGH. Unreal: VERY HIGH.
- Browser (tonight) API specifics, from the r186 examples: import * as THREE from 'three/webgpu'; import { pass, mrt, output, normalView, velocity } from 'three/tsl'; import { ssgi } from 'three/addons/tsl/display/SSGINode.js'; import { traa } from 'three/addons/tsl/display/TRAANode.js'; also GTAONode.js (ao), BloomNode.js and TAAUNode.js. Create the renderer with const r = new THREE.WebGPURenderer({antialias:false}); await r.init(); then const rp = new THREE.RenderPipeline(r); rp.outputNode = ...; rp.render(). For volumetrics use new THREE.VolumeNodeMaterial() with steps = 8-12 and shadow-casting spot/point lights, then denoise with gaussianBlur. WebGL2 fallback is automatic; ship quality presets (SSGI off / GTAO only on low).
- Browser secure context: WebGPU and getUserMedia both need HTTPS or localhost. A tunnel gives HTTPS. Bind Node to 127.0.0.1 so the host gets no Windows Firewall prompt (cloudflared or Tailscale Funnel connect outbound). Resume the AudioContext on a 'Click to join' gesture to satisfy autoplay rules.
- Agent test harness (browser): Playwright headed Chromium on the RTX 5090 (headless may fall back to software adapters). Flags: --use-fake-ui-for-media-stream --use-fake-device-for-media-stream --use-file-for-fake-audio-capture=C:/path/voice.wav. Spawn 4 contexts, assert voice gain falls with distance and occlusion via an AnalyserNode RMS readout, and screenshot each build. MCPs: claude mcp add playwright -- npx @playwright/mcp@latest, or claude mcp add chrome-devtools -- npx chrome-devtools-mcp@latest.
- Godot v2 pipeline: unzip Godot_v4.7.2-stable_win64.exe.zip (86 MB) and use Godot_v4.7.2-stable_win64_console.exe so agents see stdout. Run 'Godot_console.exe --headless --path <proj> --import' once (creates .godot/ and .uid files), then 'Godot_console.exe --headless --path <proj> --export-release "Windows Desktop" build/win/TheBoys.exe' (the preset must exist in export_presets.cfg). Templates go in %APPDATA%/Godot/export_templates/4.7.2.stable/ (windows_release_x86_64.exe, its console exe, version.txt). The 1.28 GB TPZ is a zip, so those 3 files can be pulled with HTTP range requests if bandwidth is tight.
- Godot visual checks: --headless uses a dummy renderer, so it produces no pixels. For screenshots run windowed on the host GPU: '--path . --write-movie shots/f.png --fixed-fps 30 --quit-after 240 res://tests/capture.tscn', or in script get_viewport().get_texture().get_image().save_png(). Use '--check-only --script' for parse checks. A Godot MCP (claude mcp add godot -- npx @coding-solo/godot-mcp) adds run, stop and debug-output tools.
- Godot text authoring: header '[gd_scene format=3 uid="uid://..."]'; omit load_steps (deprecated from 4.6). Keep hand-written .tscn files tiny and build levels at runtime from GDScript (GridMap/MeshLibrary or CSG blockout, NavigationRegion3D.bake_navigation_mesh(true) at runtime, Jolt physics default in 4.6+). Commit .uid and .import files, ignore .godot/.
- GodotSteam setup: unzip godotsteam-4.23-gdextension-plugin-4.4.zip into res://addons/godotsteam (it carries steam_api64.dll). Enable auto-init in Project Settings with app_id 480 (or call Steam.steamInitEx(480, true) in an autoload) and call Steam.run_callbacks() each frame unless embedded callbacks are on. Ship steam_api64.dll next to the exe. The Steam client must be running and logged in.
- GodotSteam lobbies and invites: Steam.createLobby(Steam.LOBBY_TYPE_FRIENDS_ONLY, 4) leads to lobby_created, then Steam.setLobbyData(id, 'game', 'theboys-v1') and Steam.activateGameOverlayInviteDialog(id). Joiners: connect Steam.join_requested, and also parse '+connect_lobby <id>' from OS.get_cmdline_args(). For searching: Steam.addRequestLobbyListDistanceFilter(Steam.LOBBY_DISTANCE_FILTER_WORLDWIDE); Steam.addRequestLobbyListStringFilter('game', 'theboys-v1', Steam.LOBBY_COMPARISON_EQUAL); Steam.requestLobbyList(). Then peer = SteamMultiplayerPeer.new(); peer.create_host(0) or peer.create_client(Steam.getLobbyOwner(id), 0); multiplayer.multiplayer_peer = peer.
- GodotSteam proximity voice: Steam.startVoiceRecording() (push-to-talk or open mic). Each frame, var v = Steam.getVoice(); when v.result is OK and v.written > 0, send v.buffer through an unreliable RPC (or Steam Networking Messages). On receive, var d = Steam.decompressVoice(buf, 48000); convert d.uncompressed s16 to PackedVector2Array and push_buffer() into the AudioStreamGeneratorPlayback of an AudioStreamPlayer3D parented to the speaker's head. Settings: attenuation_model ATTENUATION_INVERSE_DISTANCE, unit_size about 3, max_distance about 25. Occlusion: raycast from the listener and, when blocked, lower attenuation_filter_cutoff_hz to about 800 and volume_db by -6. Walkie-talkie: route to a 2D AudioStreamPlayer on a band-pass plus distortion bus. Consider 24 kHz and buffer_length 0.1-0.2 s, because GDScript sample loops cost CPU.
- Godot without Steam: ENetMultiplayerPeer (UDP; port-forward, or every player joins the host's tailnet via Tailscale node sharing) for local or automated tests; WebRTCMultiplayerPeer with webrtc-native 1.2.2 plus a signaling server for NAT traversal. Voice then needs AudioEffectCapture on a mic bus plus an Opus GDExtension (Godot-Opus). Treat this as a fallback, not the plan.
- Unity (only if chosen later): install the CLI with $env:UNITY_CLI_CHANNEL='beta'; irm https://public-cdn.cloud.unity3d.com/hub/prod/cli/install.ps1 | iex. Then unity auth login (browser sign-in, one time), unity license activate personal, unity install 6000.6.4f1 -m windows-il2cpp webgl, unity projects create --with-pipeline, unity build / unity test. Classic flow: Unity.exe -batchmode -nographics -quit -projectPath . -executeMethod Build.Win64 -logFile -. Do not hand-edit .unity/.prefab YAML; build scenes from C# in a bootstrap scene.
- Unity networking and voice (if chosen): com.unity.netcode.gameobjects 2.10.x + com.unity.services.multiplayer 2.1.x: var s = await MultiplayerService.Instance.CreateSessionAsync(new SessionOptions{MaxPlayers=4}.WithRelayNetwork()); share s.Code. Vivox: await VivoxService.Instance.InitializeAsync(); await LoginAsync(); await JoinPositionalChannelAsync('lvl', ChatCapability.AudioOnly, new Channel3DProperties(32, 1, 1.0f, AudioFadeModel.InverseByDistance)) (verify constructor order); call Set3DPosition(playerGO, 'lvl') every 0.3 s. Native builds only, since web has no positional voice.
- Unreal (only if chosen later): Engine/Build/BatchFiles/RunUAT.bat BuildCookRun -project=X.uproject -noP4 -platform=Win64 -clientconfig=Shipping -build -cook -stage -pak -archive -archivedirectory=out. Python editor scripting: UnrealEditor-Cmd.exe X.uproject -run=pythonscript -script=gen.py. UE 5.8 MCP: enable ModelContextProtocol + AllToolsets, console ModelContextProtocol.StartServer (localhost only, no auth). Proximity voice: OnlineSubsystemSteam VoIP plus UVOIPTalker with attenuation settings, not EOS voice.
- v2 distribution: own App ID ($100) enables Steam Playtest or keys, auto-updates, real overlay 'Join Game' and rich presence. Interim non-Steam option: itch.io butler push build/win user/theboys:windows (incremental patches). Code signing (Azure Artifact Signing $9.99/month) only if the user is in the US/Canada or has an EU/UK organisation.
- Search budget note: the shared WebSearch quota ran out near the end, so these were NOT verified live and come from prior knowledge: the Windows Defender Firewall prompt fires only for listening sockets; accepting a 480 invite while the build isn't running launches Spacewar; Steam P2P cannot connect to the same account on one PC; steamworks.js lobby and networking coverage; UE compile and cook times; GUT test-runner version.

## Key facts
- (high) Godot latest stable is 4.7.2-stable, published 2026-08-18. 4.7 was 2026-06-18, 4.7.1 was 2026-07-14, 4.6.3 was 2026-05-20, and 4.8-dev7 was published 2026-10-01 at feature freeze, with no 4.8 stable date announced. [https://github.com/godotengine/godot/releases/tag/4.7.2-stable]
- (high) Godot 4.8 dev 7 is the feature-freeze snapshot (symbol renaming, animated decals, zero-allocation physics queries); its notes contain nothing on web, WebGPU or networking. [https://godotengine.org/article/dev-snapshot-godot-4-8-dev-7/]
- (high) Godot 4.7 added the AreaLight3D rectangular light, HDR output (Windows, macOS, iOS, visionOS, Linux Wayland; not web; Forward+ or Mobile only), clearcoat energy-conservation fixes, nearest-neighbour 3D scaling, and only groundwork for Vulkan ray tracing. [https://godotengine.org/releases/4.7/]
- (high) Godot 4.6 (2026-01-26) overhauled SSR (full or half resolution), moved glow before tonemapping, exposed AgX parameters, switched reflection probes to octahedral maps, and made Jolt the default physics engine for new 3D projects. [https://godotengine.org/releases/4.6/]
- (high) In Godot, SDFGI, VoxelGI, volumetric fog, SSIL, SSR, TAA and FSR2 are Forward+ only. The Compatibility renderer allows 8 omni/spot lights per mesh, versus 512 per cluster in Forward+. [https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html]
- (high) Godot 4.7 docs: web export can only target WebGL 2.0 (Compatibility); 'Godot currently does not support WebGPU'. On web, only HTTP, WebSocket client and WebRTC networking work, and AudioEffects are not supported in the default sample playback mode. [https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html]
- (high) A community Godot WebGPU backend fork (dwalter/godotwebgpu, forked from 4.6.2, beta since 2026-05-10) runs Forward+ in browsers, but the prebuilt editor is 'coming soon', Windows/Linux support is listed as TODO, and it is not upstream. [https://github.com/dwalter/godotwebgpu]
- (high) The HDDAGI global-illumination PR (#86007), intended to replace SDFGI, was closed unmerged (last updated 2026-02-07), so SDFGI, VoxelGI and LightmapGI remain Godot's GI options. [https://github.com/godotengine/godot/pull/86007]
- (high) Godot CLI flags: --headless (display headless, audio Dummy), --import (import, then quit), --export-release <preset> <path>, --export-debug (implies --import), --export-pack, --check-only (with --script), --write-movie (fixed-FPS PNG/AVI capture), --quit-after N. [https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html]
- (high) Godot 4.7.2 downloads: win64 editor zip 86.0 MB; full export_templates.tpz 1281.3 MB. Inside it, windows_release_x86_64.exe is 109.3 MB (37.9 MB compressed) and web_nothreads_release.zip is 10.2 MB. [https://github.com/godotengine/godot/releases/tag/4.7.2-stable]
- (high) TSCN format from 4.6 on: load_steps is deprecated, nodes may carry unique_id, and ext_resource has type/uid/path/id. Since 4.4, scripts and shaders get sidecar .uid files; invalid UIDs fall back to the text path with a warning. [https://docs.godotengine.org/en/stable/engine_details/file_formats/tscn.html]
- (high) GodotSteam v4.23 (2026-10-05) ships a prebuilt editor win64-g472-s165-gs423-editor.tar.xz (71.9 MB; Godot 4.7.2, Steamworks SDK 1.65) and godotsteam-4.23-gdextension-plugin-4.4.zip (27.6 MB, Godot 4.4+). Since 4.22 (2026-08-22) the module and GDExtension share one codebase. [https://codeberg.org/godotsteam/godotsteam/releases]
- (high) GodotSteam's SteamMultiplayerPeer plugs into Godot high-level multiplayer: create_host(0) or create_client(lobby_owner_steam_id, 0), server_relay=true; works with MultiplayerSpawner, MultiplayerSynchronizer and RPCs. GodotSteam Server builds lack MultiplayerPeer. [https://godotsteam.com/tutorials/multiplayer_peer/]
- (high) GodotSteam lobbies: createLobby(type, max up to 250), setLobbyData, activateGameOverlayInviteDialog, the join_requested signal, and the +connect_lobby <id> launch argument. The docs warn that app 480 has 'tons of other test and junk lobbies', so filter on your own lobby data. [https://godotsteam.com/tutorials/lobbies/]
- (high) GodotSteam voice tutorial: startVoiceRecording / getVoice / decompressVoice (SAMPLE_RATE 48000, or getVoiceOptimalSampleRate) feeding AudioStreamGenerator.push_buffer. It is non-positional. getAvailableVoice exists again from 4.19. Steam's echo cancellation caused choppy audio in the author's tests. [https://godotsteam.com/tutorials/voice/]
- (high) The Steam Voice API only captures and compresses: the game must send the data itself and should call GetAvailableVoice each frame. There is no 3D or positional support. [https://partner.steamgames.com/doc/features/voice]
- (high) Steam Datagram Relay carries P2P traffic from ISteamNetworkingSockets (e.g. CreateListenSocketP2P) over Valve's backbone, hiding IPs, with a fallback to direct UDP or NAT punch. [https://partner.steamgames.com/doc/features/multiplayer/steamdatagramrelay]
- (medium) App ID 480 (Spacewar) lobby listing returned nothing for days in Nov 2025, later fixed. A separate forum claim that 480 never creates lobbies came from ChatGPT and contradicts GodotSteam's own 480-based tutorials. [https://forum.godotengine.org/t/godotsteam-lobbies-not-visible/127733]
- (high) Godot AudioStreamGenerator: buffer_length defaults to 0.5 s (shorter means lower latency and more CPU); the docs say the class is best used from C# or GDExtension for performance. [https://docs.godotengine.org/en/stable/classes/class_audiostreamgenerator.html]
- (high) Godot's built-in MultiplayerPeers are ENet, WebRTC and WebSocket. ENet is UDP-only, so internet play needs UDP port forwarding (or a VPN such as Tailscale). [https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html]
