Example maps: map_demo.png, map_s42.png. Suggested repo layout: shared/procgen/*, shared/nav/*, client/level/*, tools/gen-cli.ts.
- Data model: Rect{x,y,w,h}. Space{id, kind:'corridor'|'room', rect, zone, type, dist, perimeter}. Door{id, a, b (a=-1 is outside), x, y, dir:'v'|'h', len, kind:'open'|'door'|'locked'|'blocked'|'exit', lock}. Item{kind, space, x, y, data}. Level{seed, W, H, owner:Int32Array(W*H), spaces, doors, items, entrance, zones, metrics}. Edge convention: a 'v' edge on line x separates cells (x-1,y) and (x,y) and spans y..y+len; an 'h' edge on line y separates (x,y-1) and (x,y). World mapping: cell x maps to +X metres, cell y maps to +Z metres.
- Generation steps: (1) streams rngFor(seed, stage) for layout/doors/zones/place/decor. (2) Corridor lattice: corridor width 2; margins int(4,7) per side; number of blocks nb = round(span/(2+11)); block sizes from partition(total, nb, min 6). (3) Blocks between present lines, plus 4 perimeter strips, each run through BSP. (4) Scan every v and h edge into a map from space pair to edge list, then merge contiguous edges into runs. (5) Doors (rules in recommendations), then the connectivity fixer, the entrance (bottom perimeter room nearest the centre, 2-wide exit door), fire doors, and rubble with a BFS connectivity check after each change. (6) Zones and locks. (7) Dijkstra from the entrance with Manhattan centre-to-centre weights (exact, engine-independent; never Math.hypot). (8) Placement. (9) Metrics: cyclomatic number E-V+1, loopsZone0, deadEnds, unreachable, maxDist. Retry with `${seed}#${n}`.
- RNG code (bryc): xmur3(str) gives the hash seeder; sfc32(a,b,c,d) gives the generator. makeRng(seed, stage){ const h = xmur3(`${seed}|gen-v1|${stage}`); const f = sfc32(h(),h(),h(),h()); for(15) f(); } with helpers int(lo,hi) inclusive, chance(p), pick, Fisher-Yates shuffle. Use only (x>>>0)/4294967296, Math.imul, Math.floor and integer arithmetic. Break ties in every sort with `|| a.id - b.id`.
- Wire protocol: on round start the server sends {v:GEN_VERSION, seed, W, H, spaces:[[isRoom,x,y,w,h,zone,type]], doors:[[a,b,x,y,dir,len,kind,lock]], items:[[kind,space,x,y]], hash}. Clients rebuild owner[] from the rects. Door state changes are small delta messages {doorId, open|locked}. Gameplay never depends on client-side randomness.
- Geometry constants: wall height H=3.0 m, wall thickness T=0.16 m, door height 2.1 m, texture tile 2 m. Quad UVs: u = (normal along X ? z : x)/tile, v = (normal along Y ? z : y)/tile. Wall runs span [start+T/2, end-T/2]. A post at a grid vertex emits a face only on sides where no wall edge continues; these are jambs and outside corners. Lintel: 2 faces from 2.1 m up to H, plus a soffit quad with normal (0,-1,0). Then per-space mergeGeometries(geos, true) with a material array, e.g. ['floorRoom','ceiling','wall','trim'].
- Visual tricks at no cost: split wall quads at 1.1 m into wallLower/wallUpper materials (hospital/facility wainscot); baseboard strips (0.12 m) along each run; door frames as one InstancedMesh scaled by len; ceiling fixtures as an InstancedMesh with an emissive material; decals as instanced PlaneGeometry 5 mm off the wall with polygonOffset:true, polygonOffsetFactor:-1, depthWrite:false, one InstancedMesh per decal texture. Rubble on 'blocked' corridor edges uses instanced debris props.
- Props: snap to cells. Wall-hugging props (shelves, lockers, beds, cabinets) go on cells next to a wall edge and never on the cell in front of a door. Centre props (tables, gurneys) only in rooms >= 4x4, keeping a 1 m walkable ring. Record blocked cells in Uint8Array blockWalk[W*H] and blockSight[W*H] (tall props) and feed both to A* and LOS.
- Culling loop: cur = owner[floor(cam.z)*W + floor(cam.x)]. BFS over doors where (kind==='open' || doorOpen[id]) up to depth 3. For each space, group.visible = inSet, and its lights get intensity 0 when outside the set. Keep the light count constant to avoid shader recompiles. Use ClusteredLighting: `import { ClusteredLighting } from 'three/addons/lighting/ClusteredLighting.js'; renderer.lighting = new ClusteredLighting();`.
- Server AI: canCross(grid, x, y, dx, dy, doorOpen), A* with flatqueue (`import FlatQueue from 'flatqueue'`), Manhattan heuristic, door cost +2. Smooth paths by skipping waypoints while LOS (two rays offset by ±radius) is clear. Tick 10-20 Hz; recompute a monster's path at most 2 Hz or when a door changes. Vision: range 14 m x lightFactor (flashlight on or lit room 1.5, dark 0.6), FOV 110°, then LOS. Hearing: soundFlood(cell, budget = loudness in metres; footsteps run 10, walk 4, crouch 1.5, voice 4-16 from RMS, door slam 18; open door +1, closed door +6); a monster hears if d[monsterCell] <= budget.
- navcat later: `import { generateSoloNavMesh } from 'navcat/blocks'; import { findPath, DEFAULT_QUERY_FILTER } from 'navcat';` input = floor quads + wall boxes (navgeo.ts). Options: cellSize 0.15, cellHeight 0.2, walkableRadiusWorld 0.25, walkableRadiusVoxels ceil(r/cs), walkableHeight 1.8, walkableClimb 0.4, minRegionArea 8, mergeRegionArea 20, maxSimplificationError 1.3, maxEdgeLength 12, maxVerticesPerPoly 5. Rule: door clear width >= 2*ceil(r/cs)*cs + 2*cs. Doors: copy examples/src/example-doors-and-keys.ts (markBoxArea(box, DOORS_AREA_START+doorId, chf) and a passFilter that checks the key set). Crowd: crowd.create(maxRadius), crowd.addAgent(crowd, navMesh, pos, params), crowd.requestMoveTarget(crowd, id, nodeRef, pos), crowd.update(crowd, navMesh, dt).
- Difficulty scaling per day d and player count n: W = 40 + 8*min(d,4) + 4n, H ≈ 0.75W; locks: d1 = 0-1, d2-4 = 2, d5+ = 3; difficulty = min(1, 0.15d) drives rubble, broken lights and objective count; monster budget 2 + d + 0.5n, spawn interval 120 s falling to 60 s; hiding-coverage radius 14 m rising to 22 m; total loot value about quota x 1.3. Small 40x30 maps give a cyclomatic number of about 4, good for day 1.

## Key facts
- (high) DunGen connects two doorways only if both share the exact same Socket asset (custom code-based connection rules can override). Connector objects spawn when a doorway connects, Blocker objects when it stays unused; on equal priority the choice is random. A doorway must sit on the edge of the tile's axis-aligned bounding box with local +Z pointing outward. [https://dungen-docs.aegongames.com/2.18/core-concepts/doorways/]
- (high) DunGen Dungeon Flow: main path Length (Min/Max) in tiles; branch modes Local/Global/Section with Branch Count; loops via 'Connection Chance' (0-1), the chance that two unconnected but overlapping doorways are joined; Special Tile Injection. [https://dungen-docs.aegongames.com/2.18/core-concepts/dungeon-flow/]
- (high) DunGen lock and key: Key Manager asset; lock placement Entrance/Exit/Any; keys guaranteed to sit before their locks along the main path; runtime interfaces IKeySpawner.SpawnKey() and IKeyLock.OnKeyAssigned(). [https://dungen-docs.aegongames.com/2.18/advanced-features/lock-key-system]
- (high) DunGen culling strategies: Adjacency (current tile plus BFS to Adjacent Tile Depth, optional Cull Behind Closed Doors, stable CPU cost), Frustum (per tile), Portal (frustum projected through doorways, variable cost). [https://dungen-docs.aegongames.com/2.19/optimization/culling/]
- (medium) Lethal Company interiors are built with DunGen (community interior mods describe themselves as DunGen interiors, e.g. Black Mesa with 130+ room tiles). [https://thunderstore.io/c/lethal-company/p/Plastered_Crab/Black_Mesa_Half_Life_Moon_Interior/]
- (medium) R.E.P.O. assembles levels from module lists (start rooms, corridors, dead ends, extractions). Extraction points go in outer rooms with one entrance; 4-connection rooms go in the interior and 1-3-connection rooms on the outer edge. [https://thunderstore.io/c/repo/p/CbIPOK_Studio/Difficulty_Editor/]
- (high) Unexplored's cyclic generator starts from a loop with entrance and goal attached (two arcs) and has 24 cycle types (e.g. two alternative routes, ThreeLeverHub). It refines a 5x5 node grid, expanded x2 then x5 into a tilemap, using about 5000 rewrite rules. Dormans: small levels are more interesting to generate than large ones. (2017 game, 2021 article.) [https://www.boristhebrave.com/2021/04/10/dungeon-generation-in-unexplored/]
- (high) Cycle patterns that beat trees: alternative paths with different risk, lock-and-key cycle, shortcut, nested cycles, one-way passages (e.g. collapsing bridge). [https://www.gamedeveloper.com/design/unexplored-s-secret-cyclic-dungeon-generation-]
- (high) Metazelda key levels: to get key n you need keys 1..n-1; key n is placed in the highest-intensity room of key level n-1, so puzzles are solvable by construction (older Java project). [https://github.com/tcoxon/metazelda]
- (high) Nystrom's Rooms and Mazes: rooms on odd coordinates, maze fill, spanning-tree merge via connectors, a small chance of opening extra connectors for loops, then removal of dead ends (2014, older source). [https://journal.stuffwithstuff.com/2014/12/21/rooms-and-mazes]
- (high) Hitman (GDC Europe 2015) sound propagation uses rooms and portals to muffle sounds occluded by walls and make sounds appear to come from openings, with simplifications such as one material per room (older source). [https://gdcvault.com/play/1022774/Sound-Propagation-in]
