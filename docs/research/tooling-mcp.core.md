# tooling-mcp

## Executive summary
I tested this on the host itself with throwaway scripts in the scratchpad. Playwright 1.63 driving the installed Chrome 154 (channel 'chrome') in headless mode gets a real hardware WebGPU adapter (vendor nvidia, architecture blackwell, timestamp-query available), and WebGL also runs on the RTX 5090 (ANGLE D3D11). Screenshots capture the WebGPU canvas correctly and no flags are needed. Headless rendering is capped at about 233-240 fps; with --disable-gpu-vsync --disable-frame-rate-limit it ran at 5,539 fps. Each browser process can be fed its own WAV file as a fake microphone (verified with 440 Hz and 880 Hz). Two headless Chrome processes connected over WebRTC on localhost in about 150 ms with no STUN server. Four isolated contexts in one browser each rendered WebGPU at about 235-240 fps. One important finding: in Chrome 154, remote WebRTC audio sent into WebAudio is completely silent unless the stream is also attached to a muted <audio> element. The proximity-voice code must do this, and an automated two-browser voice test catches it. So the main test tool should be plain Playwright scripts kept in the repo, not an MCP: they handle several clients, distinct voices, screenshots, console errors, Chrome traces and CDP metrics, and agents view the PNG output with Read. For interactive debugging, add chrome-devtools-mcp 1.10.1: it saves perf traces to a file, reads the console with source maps, opens isolated contexts, takes --chrome-arg, throttles CPU, takes heap snapshots, and can attach to the user's running Chrome during the playtest. Playwright MCP 0.0.83 or Playwright CLI 0.1.22 is an option where held keys or named multi-browser sessions are needed; the Playwright team itself recommends the CLI plus skills over MCP for coding agents. For assets: download CC0 Poly Haven assets directly (521 models, 865 textures, 997 HDRIs, glTF at 1k-4k), compress them with gltf-transform 4.5.1, and use Blender 5.2.2 headless for conversion. MCP for Blender 2.1.8, Meshy MCP 0.6.0 (needs paid API credits), ElevenLabs, Cloudflare, GitHub and game-engine MCPs are optional. Windows gotchas, verified: Git Bash rewrites '/c' as 'C:/', and launching npx without a shell fails with ENOENT while uvx works. So add servers from PowerShell or with an explicit args array, and update Claude Code from 2.1.214. Recommendation: tonight, run claude update, have the agents build the Playwright harness, add chrome-devtools-mcp and Context7, and install portable cloudflared, ffmpeg and gltf-transform. Blender plus MCP for Blender is optional. Leave everything else until after the first playtest.

## Risks
- Windows stdio MCP spawn failures. Bare npx fails with ENOENT (verified), and running 'claude mcp add ... -- cmd /c npx' from Git Bash turns /c into C:/ (verified), so the server never starts. => Run claude mcp commands in PowerShell, or write .mcp.json or add-json with an explicit args array ['/c','npx',...]. Use bare uvx for Python servers. Check with 'claude mcp get <name>'. In Git Bash use MSYS_NO_PATHCONV=1 or //c.
- Remote WebRTC audio is silent in WebAudio unless attached to a muted <audio> element (verified on Chrome 154), which would break proximity voice and show up only when friends join. => Implement the muted-element workaround and run the two-process fake-mic test (webrtc_voice_probe.js pattern) in CI before every playtest.
- Chrome does not apply echo cancellation to audio played through WebAudio (reported in third-party known-issues docs; not verified here), so friends on speakers will hear echo through proximity voice. => Default to push-to-talk, recommend headphones, apply noiseSuppression/echoCancellation/autoGainControl on the mic constraints, and consider a loopback-PC AEC workaround later.
- WebGPU and getUserMedia need a secure context. Friends opening a plain http://<tailscale-ip>:port URL get no WebGPU and no mic. => Invite through an HTTPS tunnel (cloudflared quick tunnel, or Tailscale Serve/Funnel with HTTPS). Keep a WebGL2 fallback path for anyone whose adapter request fails.
- Headless tests run on an RTX 5090 at a 240 fps cap, which hides performance problems on friends' mid-range GPUs. => Benchmark uncapped, keep GPU-time budgets from timestamp queries (e.g. under 4 ms at 1080p on the 5090), use DevTools MCP emulate cpuThrottlingRate=4, and ship a medium preset.
- MCP browser windows (headed by default in both DevTools MCP and Playwright MCP) pop up on the host's desktop, or persistent-profile locks collide when parallel subagents share one profile. => Pass --headless and --isolated; give each subagent its own isolated context (new_page isolatedContext) or a separate user-data-dir.
- Telemetry and data leakage: chrome-devtools-mcp sends usage stats and CrUX URL lookups to Google by default; MCP for Blender sends anonymous usage by default; MCP for Blender's socket server on port 9876 is unauthenticated and runs arbitrary Python. => Use --no-usage-statistics --no-performance-crux and DISABLE_TELEMETRY=true, keep Blender on localhost, set BLENDER_MCP_SAFE_MODE=1 when generated code is untrusted, and save .blend files before running execute_blender_code.
- UAC prompts from MSI installs (Blender via winget, cloudflared via winget) block unattended agents, and nobody may be at the GUI to approve them. => Use portable artifacts (Blender zip, cloudflared exe, Gyan.FFmpeg portable), or have the user run the winget commands once in an elevated terminal.
- Agents run up paid API spend (Meshy credits, ElevenLabs, Hyper3D/Hunyuan cloud) or pull in CC-BY assets without attribution (Sketchfab, about 69% of Poly Pizza, free-tier Meshy outputs are CC BY 4.0). => Require explicit user approval for paid generation, check check_balance/check_subscription first, prefer CC0 sources (Poly Haven, licence='CC0' filter), and keep an assets/CREDITS.md generated from import metadata.
- The installed Claude Code (2.1.214) is behind (2.1.29x is current) and lacks MCP image-to-file saving (2.1.283+) and later Windows fixes. => Run claude update before starting the build.
- API keys committed through project-scoped .mcp.json, or ANTHROPIC_API_KEY exported into Claude Code's environment, which switches Claude Code to API-key auth and turns off Claude in Chrome. => Put keyed servers at user or local scope or use ${VAR} expansion, gitignore .env, and keep the game's keys only in the Node server's environment.
- The web search budget ran out mid-research, so some secondary items were not checked live (Hyper3D Rodin and Tripo pricing, Hunyuan3D on Blackwell, Tailscale Funnel setup steps, Chromium bug numbers). => Treat those as unverified and re-check in a follow-up session before relying on them.

## Decision-critical claims
- Headless Playwright with channel:'chrome' (Chrome 154) on this Windows host uses the RTX 5090 for WebGPU with no extra flags, and screenshots capture the WebGPU canvas. Verified locally.
- --use-file-for-fake-audio-capture is per browser process, so each simulated voice needs its own chromium.launch(). Verified with 440 Hz and 880 Hz files.
- Remote WebRTC audio fed to WebAudio in Chrome 154 is silent unless the stream is also attached to a muted <audio> element. Verified, including a 6-second control run.
- Local headless-to-headless WebRTC connects without STUN/TURN, so local tests do not exercise NAT traversal. Friends' connectivity still needs STUN/TURN and can only be validated with a real remote peer.
- Since Playwright 1.57 the default headless browser is chrome-headless-shell, whose WebGPU support is untested here. Tests must set channel:'chrome' (or 'chromium').
- In Git Bash, '/c' becomes 'C:/', and Node spawn('npx') without a shell fails with ENOENT, while uvx works. Verified. Claude Code 2.1.119 removed a 'cmd /c required' warning as a false positive, so whether Claude Code itself still needs cmd /c is unconfirmed.
- Claude in Chrome needs a claude.ai login on Pro/Max/Team/Enterprise and is turned off under API-key auth. Claude Code CLI computer use is macOS-only.
- chrome-devtools-mcp supports --chrome-arg (fake-media flags), --autoConnect to a running Chrome 144+, isolated contexts per page, and saving traces and screenshots to files.
- The local ElevenLabs MCP is deprecated (hosted OAuth MCP replaces it), and its SFX tool caps clips at 5 s while the REST API allows 0.5-30 s.
- Meshy API use requires purchased API credits; the free plan's 100 web credits do not cover API calls.
- Cloudflare Quick Tunnels allow 200 in-flight requests, do not support SSE, and change hostname every run. WebSockets are not listed as restricted.
- WebGPU and getUserMedia require a secure context, so friends must connect over HTTPS, not raw Tailscale http IPs.
