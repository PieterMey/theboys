# netcode-hosting

## Executive summary
Run one authoritative Node 24 process on the host PC. It serves the built client and a WebSocket endpoint on the same port (127.0.0.1:3000), and it runs monster AI, items, objectives, progression and all Claude calls, so the API key never reaches a browser. Do not host the game in a player's browser over P2P (Trystero 0.26 or PeerJS 1.5.5): the Claude key would have nowhere safe to live, Chrome throttles hidden-tab timers to 1 Hz (rendering stops completely), and the game dies when the host leaves. For netcode, use raw ws 8.22.0 plus msgpackr 2.1.0 with a small shared-TypeScript protocol. Colyseus 0.18.9 is the strongest framework option: it has rooms, joinById codes, built-in reconnection, StateView interest management, WebRTC signaling and a Vite plugin. But 0.18 shipped between May and August 2026 with heavy API churn, so agents would be coding against an API they barely know. UDP transports (geckos.io 3.1, WebTransport, an SFU on the PC) cannot pass through any of tonight's tunnels. For invites, use a Cloudflare Quick Tunnel: no account, valid HTTPS (getUserMedia needs a secure context) and full WebSocket support. I tested one live on this PC with cloudflared 2026.10.0. It connected over QUIC to Zurich (zrh01) with one connection. At 20 Hz, round-trip time from the PC to the edge and back was about 20 ms median and 31-35 ms at p90, the same for 1 and 8 clients. A 20 MiB download ran at 42 Mbps, and the edge cached nothing (CF-Cache-Status DYNAMIC). The URL stayed the same when the game server restarted. An idle socket was killed at 125.7 s, and server pings every 30 s kept it alive. Twice during testing there was a 1-2 minute window with a median of 75-195 ms, so interpolation must adapt and gameplay must be forgiving. Tailscale Funnel (1.98.4 is installed) is only a backup: it needs a one-time admin consent click, has undisclosed bandwidth caps and an open bug that strips query strings on WebSocket upgrades. ngrok free is ruled out by its 1 GB/month cap and warning page, and playit.gg free has no HTTPS. Netcode plan: a fixed 30 Hz simulation loop (setInterval(33) on this Windows host actually ran at 21 Hz), 20 Hz snapshots, client-authoritative player movement checked against the shared level grid, everything else server-authoritative, a reliable event stream, full state on join or resume, and a 100 ms adaptive interpolation buffer. Expect about 50-60 kbps down per client and about 0.5 Mbps host upload at 8 players, plus seed-only level sync. Recommendation: Node 24 + ws + msgpackr behind a Cloudflare Quick Tunnel tonight, with Tailscale Funnel as the fallback. Later, get a stable URL with a named tunnel and your own domain, or move to a Hetzner CX23 (about €5.49/month) near Zurich.

## Recommendations
- [TONIGHT] Authoritative Node 24 server on the host PC: one process, one port (listen on 127.0.0.1:3000) serving the production client build plus the WebSocket endpoint. Monster AI, items, doors, objectives, economy, progression and Claude calls all run server-side. -- Keeps the Claude and JEV keys off clients. The PC is always present, so the 'host' never leaves. Hidden-tab throttling cannot stall the simulation. A single origin means a single tunnel URL. Binding to 127.0.0.1 avoids the Windows Firewall prompt, since tunnels connect locally.
- [TONIGHT] Netcode library: ws 8.22.0 (server; Node bots can use ws or Node's built-in WebSocket) plus msgpackr 2.1.0, with a hand-written protocol in packages/shared/protocol.ts (opcode tuples, quantized ints). -- The API has been stable for years, so agents know it well. The agent can see and debug every line. Headless bot tests are trivial. It works through any HTTPS tunnel. ws defaults are already right for games (setNoDelay on, permessage-deflate off). About 500-800 lines covers rooms, codes, resume, snapshots and signaling relay.
- [TONIGHT] Cloudflare Quick Tunnel as the primary invite path: download cloudflared.exe (2026.10.0) into tools/ (no admin), run it in its own terminal with --metrics 127.0.0.1:20241, and have the game server read GET /quicktunnel to build the invite link. -- No account, real HTTPS, WebSockets verified live. The URL survives game-server restarts, so agents can redeploy all night without re-inviting anyone. Measured overhead: about 20 ms median, 33 ms p90. winget/MSI installs can raise a UAC prompt that a non-interactive agent cannot click.
- [TONIGHT] Heartbeats: ws.ping() every 20-30 s from the server (ws README isAlive pattern, terminate on a missed pong), plus an app-level Ping/Pong every 2 s for RTT and clock offset. -- Measured: an idle WebSocket through the tunnel closed at 125.7 s (code 1006), and survived 200 s with 30 s ping frames. Lobby and menu screens can be silent for longer than 125 s.
- [TONIGHT] Tick model: fixed 30 Hz simulation driven by a performance.now() accumulator woken by setTimeout(loop,1); 20 Hz snapshots on their own accumulator; clients send their own pose at 20 Hz from the render loop; remote entities rendered about 100 ms in the past (adaptive 80-250 ms from measured jitter). -- Measured on this Windows host: setInterval(33) ran at 21.4 Hz and setInterval(50) at 16.1 Hz, while the accumulator hit 29.95 Hz. Jitter spikes seen through the tunnel need a buffer that adapts.
- [TONIGHT] Authority split: client-authoritative player movement (server clamps speed, rejects teleports and non-walkable tiles using the shared grid); server-authoritative monsters, perception, item pickup arbitration, damage, objectives, credits and unlocks. Send a 1-byte voiceLevel with each pose so monsters can hear voice chat. -- Standard for co-op and cheating doesn't matter. It needs no client prediction or reconciliation code. Proximity-voice loudness doubling as monster noise makes sneaking and teamwork part of the netcode at almost zero cost.
- [TONIGHT] Sync model: a reliable ordered event stream (doors, items, objectives, deaths, LLM lines) plus superseding transform snapshots; a full state dump in Welcome on join and resume; skip snapshots (never events) for sockets with bufferedAmount above 64 KB. -- WebSockets are reliable and ordered, so events can't be lost while connected, and late join and reconnect share one code path. Back-pressure handling stops a slow friend from building up seconds of lag.
- [TONIGHT] Reconnection: random resume token per session (sessionStorage) plus a persistent playerKey (localStorage); client retries with backoff of 250 ms doubling to a 4 s cap, with jitter, for up to 2 minutes; the server holds the slot for 90 s (avatar frozen as 'unconscious'); if the token is unknown (server restarted), the player rejoins the lobby as a fresh join. -- Cloudflare documents that it restarts servers and drops WebSockets. The quick tunnel runs a single connection (ha-connections:1). Agents will restart the server mid-session.
- [TONIGHT] Deterministic level generation in packages/shared: integer PRNG (sfc32/mulberry32 via Math.imul, or pure-rand 8.4.2), simplex-noise 4.0.3 seeded with that PRNG, only + - * / sqrt floor in generation decisions. Server sends {seed, genVersion, params, gridHash}; client checks an FNV-1a hash; on mismatch the server sends the raw grid (a few KB). -- Bandwidth stays near zero, and the server gets the same grid for A* pathfinding, line-of-sight and movement checks. MDN warns that Math function precision varies by engine (V8 vs SpiderMonkey for Firefox friends). The hash plus fallback turns a desync into a non-event.
- [TONIGHT] Lobby: 4-letter crew code from consonants only (e.g. BCDFGHJKLMNPQRSTVWXZ) carried in the URL hash (https://<host>/#ABCD) and sent in the first WebSocket Hello message, never in the WebSocket URL; a 'Copy invite' button fed by GET /api/invite (from /quicktunnel); join-in-progress spawns at the ship/van; the leader role passes to the earliest-joined connected player; crew saves written atomically to saves/<code>.json after each mission; Hello carries a __BUILD_ID__ and stale clients get a reload message. -- Covers invite links, join-in-progress, host leaving and continuous redeploys. Keeping the code out of the WebSocket query string avoids the Tailscale serve/Funnel query-stripping bug (issue #18651), so the backup path keeps working.
- [TONIGHT] Voice: signal WebRTC (SDP/ICE) through the same game WebSocket as a relay; audio goes P2P over a mesh; add Cloudflare Realtime TURN (1,000 GB/month free) with server-generated short-lived credentials if any friend fails to connect. -- Media can't go through the HTTP tunnels, and P2P UDP avoids the jitter spikes the tunnel showed. Each client sends about 7 × 48 kbps when everyone talks. TURN credentials stay server-side.
- [TONIGHT] Backup exposure: Tailscale Funnel (tailscale funnel --bg 3000) for a stable https://<machine>.<tailnet>.ts.net URL. -- Already installed (1.98.4). But it needs a one-time consent click by the tailnet admin, takes up to 10 minutes for DNS, has undisclosed non-configurable bandwidth caps (slow asset loading) and routes through Funnel relays. Use it only if trycloudflare misbehaves.
- [later] Do not use tonight: ngrok free, playit.gg free, geckos.io/WebTransport/SFU on the host behind tunnels, Trystero/PeerJS host-in-browser, PartyKit/Durable Objects, uWebSockets.js. -- ngrok free: 1 GB/month egress plus a warning page in front of HTML. playit free: no HTTPS, so no microphone. UDP-based options need open UDP ports. P2P has no safe key storage and no authority. Durable Objects would mean rewriting for the Workers runtime. uWS adds nothing at 8 players.
- [later] Consider Colyseus 0.18 (colyseus 0.18.9 / @colyseus/sdk 0.18.5 / @colyseus/schema 5.0.36) for v2, pointing agents at https://docs.colyseus.io/llms.txt. -- Built-in matchmaking, joinById codes, reconnection with state reconciliation, StateView, WebRTCPlugin plus @colyseus/webrtc, request/response, and a Vite single-origin plugin. Worth it once there are many crews or rooms; not worth the API-learning risk tonight.
- [later] Later hosting: (a) keep the home server but get a stable URL with a named Cloudflare Tunnel on a cheap domain, with static assets on Cloudflare Workers Static Assets (free, unlimited requests); or (b) Hetzner CX23 in Falkenstein/Nuremberg (~€5.49/month, 20 TB traffic) with Docker and Caddy, which also opens UDP for an SFU, geckos or WebTransport. -- Quick-tunnel URLs change each time cloudflared restarts and have no SLA or edge caching. The host's tunnel landed in Zurich, so Hetzner Germany is close. Fly.io has no free tier, Render free sleeps and cut bandwidth, Railway costs about $5 or more per month.
- [later] Later optimization: once the WebRTC voice mesh exists, open an unreliable DataChannel between peers for player poses (P2P, UDP) and keep the server WebSocket for authority at 10-20 Hz. -- Remote-player motion skips the tunnel's TCP jitter and the extra hop; the server still gets poses for monster AI.

## Risks
- The quick tunnel has no SLA, runs a single connection (ha-connections:1), and its URL changes whenever cloudflared restarts. Cloudflare can restart edge servers, which drops WebSockets. => Run cloudflared in its own terminal and never restart it during the session (restart only the game server; measured that the URL survives). Clients auto-reconnect with resume tokens. The lobby always shows the live invite link from /quicktunnel. Keep the Tailscale Funnel command ready as a fallback.
- Transient latency spikes through the tunnel (observed two 1-2 minute windows with p50 75-195 ms and max ~400 ms) cause rubber-banding or unfair deaths. => Adaptive 80-250 ms interpolation buffer, extrapolation capped at 100 ms, telegraphed monster attacks (300-600 ms wind-up), server hit checks using the victim's own reported pose. Ask the host to use wired Ethernet; try --protocol http2 if spikes persist.
- Home upload becomes the bottleneck for initial asset downloads, since trycloudflare does no edge caching (every byte comes from the PC; ~42 Mbps measured on loopback). => Asset budget under ~100 MB, KTX2/meshopt compression, immutable browser caching, a progress bar, staggered joins. Later, move static assets to Cloudflare Workers Static Assets (free, unlimited) or R2.
- Idle WebSockets are cut at about 125 s (measured), for example on lobby or menu screens. => Server ws.ping() every 20 s (30 s verified to keep the connection alive) plus app-level Ping every 2 s.
- The 200 in-flight request cap on quick tunnels returns 429 when 8 clients load many assets in parallel. => Limit loader concurrency per client, bundle and atlas assets into fewer files, retry 429 with exponential backoff.
- Windows timer granularity makes setInterval loops run slow (measured 21 Hz instead of 30), so monsters move at the wrong speed and snapshots arrive at irregular rates. => A performance.now() fixed-step accumulator woken by setTimeout(loop,1) (measured 29.95 Hz); pass real dt to nothing except the accumulator.
- Agents write outdated Colyseus code (API churn from 0.15 to 0.18; 0.18 released May–Aug 2026) or misuse new Schema 5 constraints, and burn hours debugging decode errors. => Use raw ws + msgpackr tonight. If Colyseus is chosen anyway, require agents to fetch docs.colyseus.io/*.md pages and pin exact 0.18.x versions.
- Level desync between Chrome/Edge (V8) and Firefox (SpiderMonkey) from Math.sin/cos/pow precision differences or hidden non-determinism in generation. => Integer PRNG, basic arithmetic only, GEN_VERSION plus FNV-1a gridHash check, and server-sent raw grid as a fallback.
- Proximity voice fails for some friend pairs behind symmetric NAT or CGNAT (UDP media can't use the tunnel). => Add Cloudflare Realtime TURN (1,000 GB/month free) with server-generated short-lived credentials. Mesh with at most 7 peers is fine bandwidth-wise. Last resort: relay Opus frames over the game WebSocket for broken pairs.
- The public URL leaks (anyone with it can join and trigger Claude calls, which cost money). => Crew code in the URL hash plus an optional password, a kick button, per-mission and per-day LLM call caps on the server, keys only in the server .env, and optionally cloudflared --allowed-mail.
- Tailscale Funnel fallback misbehaves: undisclosed throughput cap, consent step needs the user, WebSocket query strings stripped (#18651), up to 10 minutes of DNS delay. => Keep all session data out of WebSocket URLs (send it in Hello); enable Funnel once early in the evening so DNS and certs are ready; use it only if trycloudflare fails.
- Installers (winget MSI) or UAC/firewall prompts block a non-interactive agent. => Download cloudflared.exe directly into tools/ (verified to work, no admin) and bind the server to 127.0.0.1.
- A server crash or redeploy mid-mission loses mission state; if the host PC sleeps, everyone is cut off. => Persist crew progression atomically at every mission end; clients auto-return to the lobby on resume failure; disable sleep on the host PC for the session.

## Decision-critical claims
- Cloudflare Quick Tunnels work for this game today without an account: HTTPS (secure context for mic), WebSockets, a URL that persists across game-server restarts, and measured host-to-edge-to-host RTT of about 20 ms p50 / 33 ms p90 at 20 Hz with 8 clients (Zurich edge).
- Quick-tunnel idle WebSockets are closed at about 125 s (measured 125.7 s); 30 s server ping frames prevent it (measured).
- trycloudflare does not cache at the edge (CF-Cache-Status: DYNAMIC even for immutable .js), so all asset bytes come from the host PC's uplink (~42 Mbps measured on loopback).
- UDP transports (geckos.io, WebTransport, an SFU on the host PC) cannot be exposed through Cloudflare Quick Tunnels or Tailscale Funnel; the game must use WebSocket/TCP via the tunnel, with voice media P2P via WebRTC (plus TURN).
- ngrok free is unusable for an asset-heavy browser game: 1 GB/month data transfer out, 20k requests/month, and an interstitial page in front of all HTML browser traffic.
- playit.gg free provides only raw TCP/UDP (HTTPS is Premium), so a page served that way is not a secure context and getUserMedia (voice) will not work.
- On this Windows host, Node setInterval(33) runs at about 21 Hz; the server tick must use a performance.now() accumulator (measured 29.95 Hz).
- Colyseus 0.18 (current 0.18.9) shipped May–Aug 2026 with major API changes, which is the main reason to prefer raw ws for agent-written code tonight; its SDK also passes sessionId in the WebSocket query string, which collides with Tailscale issue #18651 if Funnel is used.
- The tunnel path showed transient degradation (p50 75-195 ms for 1-2 minute windows), so the netcode must tolerate 250+ ms jitter without breaking gameplay.
- Tailscale Funnel needs a one-time consent click by the tailnet admin (an agent cannot do it) and has undisclosed non-configurable bandwidth limits.

## Open questions
- Where are the friends located relative to the host? The host's tunnel registered at Cloudflare zrh01 (Zurich), so the host is presumably in or near Switzerland. Friends elsewhere in Europe should see roughly 30-60 ms RTT; friends on other continents will see much more.
- What is the host's real uplink, and is the PC on Wi-Fi or Ethernet? 42 Mbps was measured on loopback through the tunnel (a lower bound on the combined path), and the transient spikes might be local Wi-Fi or ISP jitter. One test with Ethernet and with --protocol http2 would tell.
- What is the total first-load asset size for the 'most advanced graphics' target? It directly sets join time through a non-caching tunnel from a home uplink.
- Does the user want a stable invite URL (needs a domain on Cloudflare for a named tunnel, or Tailscale Funnel), or is a fresh trycloudflare link per session fine?
- Will any friend need TURN for voice (CGNAT, mobile hotspot, strict corporate NAT)? Cloudflare TURN needs a free Cloudflare account and a TURN key created by the user in the dashboard.
- Is Tailscale issue #18651 (WebSocket query-string stripping) present in 1.98.4, and does it affect Funnel as well as serve? Only relevant if Funnel becomes the active path.
- Not verified: whether api.trycloudflare.com rate-limits quick-tunnel creation after repeated cloudflared restarts (search budget exhausted). Treat it as a reason to start cloudflared once and leave it running.
- Not verified live: Oracle Cloud Always Free status in 2026 (page returned 403) and the exact Render bandwidth after the 2026-08-01 plan change (only a secondary source).
