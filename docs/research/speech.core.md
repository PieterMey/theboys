# speech

## Executive summary
Speech features built into the browser are not a reliable base. Web Speech recognition in Chrome and Edge sends audio to the cloud by default. Chrome 139+ can recognise on the device, but only through processLocally plus a language pack of about 60 MB per language, and Edge's local model is still behind a Canary/Dev flag. Firefox Release has no SpeechRecognition at all (its on-device Parakeet-based version exists only in Nightly). speechSynthesis gives no access to its audio, so its output cannot be spatialised or distorted. The host's RTX 5090 makes server-side STT easy. On this machine I measured faster-whisper 1.2.1 large-v3-turbo fp16 at 47-69 ms for 2.3-6.3 s clips with the language fixed (auto-detect adds about 240 ms), Parakeet-TDT-0.6B-v3 int8 on the CPU at 81-161 ms, and WebM/Opus decode through PyAV at 14 ms. Two Windows problems showed up: PyAV 19 breaks faster-whisper's decoder (pin av==16.1.0), and CTranslate2 turns off INT8 on Blackwell GPUs (use float16). For TTS, Kokoro-82M through kokoro-js 1.2.1 inside the Node host on CPU (fp32) measured a real-time factor of about 0.1 (285 ms for a 2.3 s line). It needs no Python, the weights are Apache-2.0, and it returns 24 kHz Float32 PCM. Clients feed that through a Web Audio chain (pitch-down with optional formant shift, WaveShaper distortion, ring modulation, reverse-reverb swell, a whisper layer) into an HRTF PannerNode at the ghost's position. Its q8 build is 4x slower on CPU, and the DirectML backend crashes. For higher quality later: Chatterbox-Turbo (MIT, tags like [laugh], 10 s zero-shot cloning; its torch==2.6.0 pin must be overridden for Blackwell), Dia or Orpheus for banks of non-speech sounds (groans, screams), and ElevenLabs v3/v4 for pre-rendered lines. The mimic should start the way the Skinwalkers and Mirage mods do it: replay real clips from players who opted in, kept in RAM only, captured with vad-web and labelled by STT so the AI director can pick the creepiest one for the moment. Cloning friends' voices with zero-shot models should come later and only with explicit consent. Recommendation for tonight: host-side faster-whisper with Parakeet on CPU as fallback, kokoro-js fp32 in a Node worker, native Web Audio effects, and replay-based mimicry, with no ML models running in friends' browsers.

## Recommendations
- [TONIGHT] STT on the host: faster-whisper 1.2.1 + ctranslate2 4.8.2, model large-v3-turbo, device=cuda, compute_type=float16, in a Python 3.13 sidecar (uv venv) that the Node server talks to over localhost WebSocket/HTTP. Pin language per lobby and pass the ghost and player names as hotwords. -- Measured 47-69 ms per 2-6 s clip on this RTX 5090. It works for every friend's browser, including Firefox, keeps audio on the host, and handles languages beyond English. Auto language detection costs about +240 ms, so fix the language.
- [TONIGHT] STT fallback: Parakeet-TDT-0.6B-v3 int8 through onnx-asr 0.12.0 on CPUExecutionProvider. -- Measured 81-161 ms on the 9950X3D with no CUDA setup, which makes it a safety net if CUDA DLL loading fails. It covers 25 European languages only (no Afrikaans) and hallucinates less than Whisper on noise.
- [later] Do not depend on the Web Speech API (SpeechRecognition or speechSynthesis). -- Firefox Release lacks recognition. Chrome and Edge use the cloud by default, and on-device needs a language-pack install. speechSynthesis audio cannot be routed into Web Audio. It can be an optional zero-server mode later (Chrome 139+ processLocally, Chrome 142 phrases biasing).
- [TONIGHT] Client capture: an AudioWorklet ring buffer (about 300 ms pre-roll) on the same mic MediaStream used for WebRTC voice. Downsample to 16 kHz Int16 and send it on push-to-talk release over the game WebSocket. Use @ricky0123/vad-web 0.0.31 (MicVAD, Silero v5, Float32 at 16 kHz) for hands-free segments and mimic clips. -- Sending raw PCM needs no decoding on the server and the pre-roll avoids MediaRecorder's clipped first syllable. MediaRecorder webm/opus also works: PyAV decoded it in 14 ms.
- [TONIGHT] TTS tonight: kokoro-js 1.2.1 (Kokoro-82M ONNX, dtype fp32, device cpu) in a Node worker_thread on the host. Pre-render a bank of about 50 stock lines plus each player's name at startup, and stream LLM sentences through TextSplitterStream. -- Measured RTF of about 0.10-0.12 on CPU (285 ms for a 2.3 s line, 617 ms for 6.25 s). No Python and no GPU contention with the host's own game, Apache-2.0, output is 24 kHz Float32 PCM ready for Web Audio. q8 is 4x slower and the 'dml' device crashes.
- [TONIGHT] Ghost voice design: deep Kokoro voices (bm_george, am_fenrir, am_onyx, am_michael) at speed 0.8-0.9, pitched down 4-7 semitones, with a high-passed af_nicole whisper layer, WaveShaper distortion, a 30-60 Hz ring-mod blend, a reverse-reverb pre-swell, then an HRTF PannerNode plus a room convolver. Spirit-box variant: bandpass, random gating and static. -- Kokoro cannot whisper, groan or scream, so the creepiness has to come from DSP. Every part is a native Web Audio node except the optional formant-aware pitch shift (signalsmith-stretch 1.3.2, MIT).
- [TONIGHT] Mimic monster tonight: replay real recorded clips. Opt-in per player, own-mic only, RAM-only on the host, wiped at session end. Clips are labelled by STT so the AI director chooses them by content. Playback is synced to all clients at the monster's position with slight degradation. -- No ML, no latency, and proven at scale: Skinwalkers has 17.6M downloads and Mirage 6.3M. Real voices are creepier than cloned ones and avoid the ethics and latency problems of cloning.
- [later] Later: consented zero-shot cloning with Chatterbox-Turbo (MIT, about a 10 s reference, Perth watermark) on the GPU, or Kyutai Pocket TTS on CPU (cloning weights are gated, CC-BY-4.0). Optionally OpenVoice V2 tone-colour conversion of Kokoro output. -- Lets the mimic say new sentences in a friend's voice. It needs explicit opt-in, and every model card forbids cloning without consent. Chatterbox needs a torch override for Blackwell. F5-TTS weights are non-commercial (CC-BY-NC).
- [later] Later quality upgrades: pre-render banks of non-speech sounds and hero lines offline with Dia-1.6B or Dia2 ((screams), (groans), (gasps), (inhales); Apache-2.0) or Orpheus 3B (<groan>, <sigh>, <gasp>), or ElevenLabs eleven_v3/v4 audio tags ($0.08/1K chars). Consider Kokoro-FastAPI on GPU (image tag latest-cu128) if CPU TTS competes with the game. -- Higher expressiveness than Kokoro. Pre-rendering avoids real-time GPU latency (Dia runs about 2.1x real-time on a 4090), and the cloud cost for a few hundred lines is a few dollars.
- [TONIGHT] Spirit-box mechanic: hold to talk, then host STT, then Claude (short in-character reply as structured output), then Kokoro, then radio-chopped audio played from the spirit-box item. Start static and breathing sounds the moment the button is released to hide the roughly 1-2 s pipeline. -- Needs STT, the LLM and TTS together. Lag reads as creepiness when it is masked by static.

## Risks
- CUDA DLL loading for CTranslate2 on Windows fails in the build agent's environment (different PATH, missing cuBLAS). => Install the pip nvidia-cublas-cu12 and add the DLL dirs at runtime as measured. Fall back automatically to Parakeet v3 int8 on CPU (81-161 ms). A Docker GPU image is the last resort.
- The benchmarks used clean TTS audio. Real mics in a noisy game with laughter and crosstalk will be less accurate, and Whisper invents text on silence or noise. => Use push-to-talk or VAD gating, set language, use hotwords for names, apply no_speech_prob/avg_logprob filters and a blocklist, and have Claude interpret transcripts loosely (fuzzy intent matching instead of exact strings).
- An upgrade of the dependency stack breaks STT (PyAV 19 is already incompatible with faster-whisper 1.2.1; CTranslate2 INT8 is disabled on Blackwell). => Pin av==16.1.0, faster-whisper==1.2.1, ctranslate2==4.8.2 and compute_type float16 in a lockfile (uv pip compile), and smoke-test transcription at server startup.
- CPU TTS (kokoro-js fp32 spreads across many threads) competes with the host's own browser game and the Node tick loop, causing frame or tick hitches. => Run TTS in a worker_thread or child process, pre-render stock lines at startup, cap reply length (about 12-20 words), and move to Kokoro-FastAPI on GPU (latest-cu128) if hitches appear.
- The talk-to-ghost pipeline (upload + STT + LLM + first-sentence TTS + playback) takes about 1-2 s and could feel unresponsive. => Stream the LLM into TextSplitterStream so the first sentence plays after about 0.3 s of TTS. Play static or breathing immediately on push-to-talk release, use pre-rendered reaction lines for common intents, and keep replies short.
- Recording or cloning friends' voices without clear consent, or clips leaking (an embarrassing replay, data stored on disk). => Make it opt-in per player with a visible indicator, capture only the player's own mic, keep clips in RAM and wipe them at session end, provide no export, and allow cloning only with a separate explicit opt-in. All of the cloning model cards (Pocket TTS, CSM, Chatterbox) forbid non-consensual impersonation.
- Licences of later models: F5-TTS weights are CC-BY-NC, XTTS-v2 is under the non-commercial Coqui Public Model License, Piper is GPL-3.0, the SoundTouch worklet is MPL-2.0, and Orpheus, CSM and Pocket TTS cloning weights are gated. => Tonight's stack (Kokoro Apache-2.0, faster-whisper MIT, Parakeet CC-BY-4.0, signalsmith MIT, vad-web ISC) is fine. Re-check licences before any public or commercial release, and accept HF gates in advance with a token if gated models are adopted.
- First-run model downloads (turbo 1.6 GB, Parakeet 0.67 GB, Kokoro fp32 0.33 GB) stall the first game launch. => Pre-download during setup, keep models in a fixed HF_HOME directory, and add a server health endpoint that reports models loaded and warmed.
- Kokoro is English-only in kokoro-js. If friends want another language (Dutch, Afrikaans), the ghost cannot speak it. => Whisper still transcribes those languages. For TTS use Piper voices (many languages, GPL) or Chatterbox Multilingual V3 later. Confirm language with the user.
- Friends on Firefox ESR or older builds throw when a mic stream is connected to a 16 kHz AudioContext. => Always use the default context sample rate and resample in the worklet or on the server (vad-web resamples internally).

## Decision-critical claims
- Host-side faster-whisper large-v3-turbo fp16 on the RTX 5090 transcribes 2-6 s clips in about 47-73 ms when language is fixed, measured on this machine with clean audio; auto-detect adds about 240 ms.
- Parakeet-TDT-0.6B-v3 int8 on the host CPU transcribes the same clips in 81-161 ms (measured), so STT works even if CUDA setup fails. English and 24 other European languages only.
- speechSynthesis output cannot be captured into Web Audio (no API in the spec), so the ghost voice must come from a model producing PCM.
- Web Speech SpeechRecognition is unavailable in Firefox Release and uses the cloud by default in Chrome and Edge, so browser STT cannot be the primary path for a mixed-browser group.
- kokoro-js 1.2.1 in Node on the host CPU with fp32 synthesises at RTF about 0.10-0.12 (measured: 285 ms for a 2.3 s line). q8 is about 4x slower and the DirectML device crashes.
- faster-whisper 1.2.1's decoder breaks with PyAV 19.0.1 and works with av==16.1.0 (measured). CTranslate2 disables INT8 on Blackwell, so float16 is required.
- Python kokoro 0.9.4 does not install on Python 3.13 (requires <3.13), and chatterbox-tts pins torch==2.6.0, which lacks RTX 5090 (sm_120) kernels.
- Replay-based voice mimicry needs no ML and is proven in Lethal Company mods (Skinwalkers 17.6M downloads, Mirage 6.3M) using RAM-only clips and synced playback.

## Open questions
- Which language(s) will the friends speak? Whisper covers Dutch and Afrikaans, Parakeet v3 covers Dutch but not Afrikaans, and kokoro-js speaks only English.
- Do all players consent to having voice clips recorded for the mimic, and later to zero-shot cloning? Should consent be per session or remembered?
- Should the ghost listen all the time (VAD segments transcribed so saying its name triggers it) or only via push-to-talk on a spirit-box item? This affects privacy messaging and host load.
- Is the user willing to create an ElevenLabs or Cartesia account for pre-rendered premium lines? No such key exists; only ANTHROPIC_API_KEY and JEV_API_KEY are available, and it is unknown whether the JEV provider offers speech endpoints.
- GPU and CPU contention on the host is untested: the host plays the 3D browser game at 4K on the same 5090 and 9950X3D that run STT and TTS.
- Not measured or verified: in-browser Whisper/Moonshine WebGPU latency on friends' mid-range PCs, Chrome's on-device language list, Dia2 and Cartesia latency, and the exact vad-web 0.0.31 option names. The shared WebSearch budget (200 calls per turn across all agents) ran out mid-research, so these come from fewer sources or none; a follow-up turn can continue the search.
- Unrelated to speech: the claude.ai Google Calendar and Google Drive connectors are unauthenticated in this session and need authorisation in claude.ai connector settings before they can be used. No speech-specific MCP is needed; an optional Hugging Face MCP would let agents browse model cards (this research used the public HF API through curl instead).
