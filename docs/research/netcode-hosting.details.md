# netcode-hosting details

## Implementation notes
- TONIGHT COMMANDS (PowerShell, in the project root): `New-Item -ItemType Directory -Force tools`; `curl.exe -L -o tools\cloudflared.exe https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe`; `tools\cloudflared.exe --version` (expect 2026.10.0). Terminal A: `npm run build; npm run start` (server on 127.0.0.1:3000). Terminal B, left running all night: `tools\cloudflared.exe tunnel --no-autoupdate --metrics 127.0.0.1:20241 --url http://127.0.0.1:3000`. Get the URL: `curl.exe -s http://127.0.0.1:20241/quicktunnel` returns {"hostname":"<words>.trycloudflare.com"}. Share https://<words>.trycloudflare.com/#ABCD on Discord; the host plays at http://localhost:3000/#ABCD (localhost counts as a secure context, so the mic works). If QUIC/UDP 7844 is blocked, add `--protocol http2`. Alternative install: `winget install --id Cloudflare.cloudflared -e`, which may raise a UAC prompt and needs a new shell for PATH.
- BACKUP COMMANDS (Tailscale Funnel, already installed, v1.98.4): `tailscale funnel --bg 3000`. The first run prints a login.tailscale.com consent URL that the user must click (enables HTTPS certs and adds the funnel nodeAttr); then wait up to 10 minutes for DNS. Check with `tailscale funnel status`; turn off with `tailscale funnel reset`. URL: https://<machine>.<tailnet>.ts.net. Never put session data in WebSocket query strings (issue #18651).
- Use 127.0.0.1 explicitly, never 'localhost', in both server.listen(3000,'127.0.0.1') and cloudflared --url. Node may resolve localhost to ::1, which breaks the origin connection, and binding 0.0.0.0 triggers the Windows Firewall dialog. All tunnel traffic reaches the origin from 127.0.0.1, so don't use remoteAddress to detect the host. Use a host admin token printed at startup instead; the cf-connecting-ip header is present only on tunnelled requests (medium confidence).
- Invite plumbing: the game server polls http://127.0.0.1:20241/quicktunnel every 2 s and exposes GET /api/invite -> {url:`https://${hostname}/#${code}`}; the lobby UI shows it with a navigator.clipboard.writeText button (and optionally a QR code). Optional script scripts/host.mjs spawns cloudflared with child_process.spawn and prints and copies the link (Windows `clip`).
- Repo layout: npm workspaces with packages/shared (protocol.ts, rng.ts, levelgen.ts, constants.ts, math.ts), apps/server (Node 24, run with `tsx watch apps/server/src/index.ts` using tsx 4.23.15, or `node --watch` relying on native type stripping, which requires .ts import extensions and no enums), apps/client (Vite 8.3.3, three.js). Use `as const` objects instead of enums so shared code also runs under Node strip-types. Type-check with TypeScript 7.0.2 `tsc --noEmit`; pin typescript@6.0.3 only if a tool needs the TS JS API.
- Static serving: serve apps/client/dist from the same HTTP server, using sirv 3.0.2 ({immutable:true, gzip:true, brotli:true, single:true}) or express 5.2.1 static. Hashed /assets/* files get Cache-Control: public, max-age=31536000, immutable; index.html gets no-cache. Precompress at build time. trycloudflare does not edge-cache (measured), so browser caching is the only cache.
- Asset loading through the tunnel: cap loader concurrency at about 6-8 requests per client and retry 429 with backoff (quick tunnel limit is 200 in-flight requests). Budget the first download to about 50-100 MB using KTX2 textures and meshopt/Draco GLB. Measured 42 Mbps loopback means 7 friends × 60 MB ≈ 80 s if everyone joins at once, so stagger joins or show a progress bar.
- Protocol (packages/shared/protocol.ts): every frame is msgpackr pack([op, ...]). Op = {Hello:1, Welcome:2, Reject:3, Ping:4, Pong:5, Pose:10, Snapshot:11, Event:12, Req:13, Reply:14, Signal:20, Chat:22}. Client to server: Hello {v:__BUILD_ID__, crew:'ABCD', key:playerKey, resume?:token, profile:{name, look}}. Server to client: Welcome {you, token, phase, seed, genVersion, gridHash, state, serverTime}. Pose: [10, seq, x_cm, y_cm, z_cm, yaw_u16, pitch_i8, anim, flags, voiceLevel_u8] at 20 Hz. Snapshot: [11, tick, serverTimeMs, [[id,x,y,z,yaw,pitch,anim]...], [[mid,x,y,z,yaw,state]...]] at 20 Hz. Event: [12, seq, type, payload] (reliable). Req/Reply: [13, reqId, type, payload] answered by [14, reqId, ok, payload] for pickups, purchases and objective interactions. Signal: [20, toId, {sdp|ice}], which the server relays with fromId.
- Encoding: create one shared `new Packr({useRecords:false})` (or useRecords with sequential:true on the ordered WebSocket stream). Quantize positions to integer centimetres and yaw to 0..65535 so msgpack emits 2-3 byte ints instead of 9-byte float64; or use useFloat32: FLOAT32_OPTIONS.DECIMAL_FIT. Set ws.binaryType='arraybuffer' on clients. Pack the broadcast once per tick and ws.send(sameBuffer) to each client.
- Bandwidth estimate, 8 players + 6 monsters: snapshot ≈ 11 B header + 8×18 B + 6×16 B ≈ 250 B payload, plus ~75 B WebSocket/TLS/TCP/IP overhead ≈ 330 B × 20 Hz ≈ 6.6 KB/s ≈ 53 kbps down per client. Host egress ≈ 53 KB/s ≈ 0.42 Mbps; host ingress ≈ 8×20×~105 B ≈ 17 KB/s. Naive JSON objects cost about 3-5x (~1.5-2 Mbps egress), still feasible. P2P voice mesh per client ≈ 7 × (32 kbps Opus + ~16 kbps RTP/SRTP/UDP overhead) ≈ 340 kbps each way at worst; it does not go through the host. Initial asset download dominates everything.
- Server loop (Windows-safe): `const STEP=1000/30; let acc=0,last=performance.now(); function loop(){const now=performance.now(); acc+=Math.min(now-last,250); last=now; while(acc>=STEP){sim.step(STEP/1000); acc-=STEP;} if(now>=nextSnap){broadcastSnapshot(); nextSnap+=50;} setTimeout(loop,1);}`. Measured 29.95 Hz. Never use setInterval(…,33): it ran at 21.4 Hz on this host. Keep Claude/LLM calls async and off this loop; deliver results as Events.
- Heartbeat (ws README pattern): `wss.on('connection', ws=>{ws.isAlive=true; ws.on('pong',()=>ws.isAlive=true)}); setInterval(()=>{for(const ws of wss.clients){if(!ws.isAlive){ws.terminate();continue;} ws.isAlive=false; ws.ping();}},20000)`. Browsers auto-reply to ping frames. Add an app Ping every 2 s carrying clientTime; the server replies with serverTime; offset = serverTime − (clientTime + rtt/2), keeping the lowest-RTT sample of the last 10.
- Back-pressure and AFK: before sending a snapshot, skip any client with ws.bufferedAmount > 65536 (snapshots supersede each other); always send Events. When a friend alt-tabs, their render loop stops sending Pose: after 2 s without one, freeze the avatar as AFK, but don't disconnect them.
- Client interpolation: keep a ring buffer of snapshots keyed by serverTime and render remote entities at estimatedServerNow − interpDelay. Start interpDelay at 100 ms; every second set it to clamp(2×50 ms + p95(arrival jitter), 80, 250). Interpolate positions linearly and yaw by shortest arc; if the buffer runs dry, extrapolate for at most 100 ms, then hold. The local player is never delayed. @geckos.io/snapshot-interpolation 1.1.1 is a drop-in if the agent prefers a library.
- Movement validation on the server: reject a Pose if distance/elapsed > maxSpeed×1.5, or if the tile at (x,z) in the shared grid isn't walkable (snap back by sending a Correction event). Monster attacks: a server-side distance check against the player's last reported pose, with a 300-600 ms telegraphed wind-up so 100-250 ms of visual delay still feels fair.
- Deterministic levelgen: `export function sfc32(a,b,c,d){return()=>{a|=0;b|=0;c|=0;d|=0;const t=(a+b|0)+d|0;d=d+1|0;a=b^b>>>9;b=c+(c<<3)|0;c=c<<21|c>>>11;c=c+t|0;return(t>>>0)/4294967296;};}`. Seed it from a 32-bit seed via splitmix32. Generation uses only + - * / Math.floor Math.sqrt (no sin/cos/pow/exp/atan2), integer grid coordinates, and ordered arrays rather than object-key iteration. Export GEN_VERSION. Compute gridHash with FNV-1a over a Uint8Array; the client checks it and on mismatch sends Req 'layout', and the server returns the grid bytes. If using rot-js 2.2.1, call RNG.setSeed(seed) immediately before generating; simplex-noise 4.0.3: createNoise2D(prng).
- Reconnect: the client keeps playerKey (crypto.randomUUID, localStorage) and resumeToken (sessionStorage). On close, retry with delay=min(4000, 250×2^n) ± 20% jitter for up to 2 minutes, showing a 'Reconnecting…' overlay. The server keeps the disconnected player for 90 s (avatar ragdolled or 'unconscious'). A resume replays Welcome with full state. An unknown token (server restarted) is treated as a fresh join into the lobby with the saved profile.
- Lobby, join-in-progress and leader: phases LOBBY (character creation, ready-up, shop) → MISSION (seeded level) → RESULTS → LOBBY. A mid-mission joiner gets Welcome, generates the level, sends Req 'levelReady', then receives the dynamic state and spawns at the ship/van. leaderId = earliest-joined connected player, reassigned 90 s after the leader drops. Only the leader can start missions; the host's admin token can kick. Write saves/<code>.json atomically (write .tmp, then fs.renameSync) at mission end and on SIGINT. If __BUILD_ID__ mismatches, send Reject {reason:'reload'} and the client reloads.
- Voice signaling over the game WebSocket: the server relays Signal frames between peer ids; clients build an RTCPeerConnection per peer (mesh, at most 7). Use iceServers [stun:stun.cloudflare.com:3478] plus Cloudflare TURN credentials fetched by the server (POST .../generate-ice-servers with ttl 86400; the Bearer token stays in the server .env). Proximity: route each remote stream through Web Audio (MediaStreamSource -> GainNode/PannerNode) driven by interpolated positions. Raise ws maxPayload to at least 64 KB (SDP can exceed 4 KB) but keep it well below the 100 MiB default.
- Abuse and cost guards: anyone with the URL can join, so require the crew code (and optionally a crew password), add a kick button, cap Claude calls per mission and per day on the server, and never ship the keys in the client bundle. Quick tunnel --allowed-mail email-PIN gating exists if extra privacy is wanted.
- Agent testing: tests/bots.mjs spawns N ws (or Node global WebSocket) clients that send Hello, then 20 Hz random-walk Pose, and asserts snapshot rate ≥ 18/s, no Reject, and that resume works after ws.terminate(). Run it against ws://127.0.0.1:3000 and wss://<tunnel>. Browser e2e with Playwright 1.63 (playwright-core works with installed Chrome): `chromium.launch({channel:'chrome', args:['--use-fake-ui-for-media-stream','--use-fake-device-for-media-stream']})` with 2-4 contexts joining the same crew, then screenshot. No extra MCP server is needed for networking or hosting.
- If the agent exposes the Vite dev server instead of the build: set server.allowedHosts: ['.trycloudflare.com','.ts.net'] and accept that friends' pages will hot-reload on every edit. Serving the production build to friends is preferred.
- If choosing Colyseus instead: npm i colyseus@0.18.9 @colyseus/schema@5.0.36 @colyseus/sdk@0.18.5 @colyseus/webrtc@1.0.0; client `new Client('/')` for same-origin; `Callbacks.get(room)` for listeners; allowReconnection in onDrop/onLeave; WebRTCPlugin needs `new WebSocketTransport({maxPayload:16*1024})`. Fetch the specific https://docs.colyseus.io/<page>.md docs rather than writing from memory.
