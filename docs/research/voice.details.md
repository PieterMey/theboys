# voice details

## Implementation notes
- Server TURN mint (Node 24, server-only env vars): const r = await fetch(`https://rtc.live.cloudflare.com/v1/turn/keys/${process.env.CF_TURN_KEY_ID}/credentials/generate-ice-servers`, {method:'POST', headers:{Authorization:`Bearer ${process.env.CF_TURN_API_TOKEN}`, 'Content-Type':'application/json'}, body: JSON.stringify({ttl: 14400})}); const {iceServers} = await r.json(); iceServers.forEach(s => s.urls = [].concat(s.urls).filter(u => !/:53(\?|$)/.test(u))); send it in the 'joined' WS message. Fallback when no key exists: [{urls:'stun:stun.cloudflare.com:3478'}, {urls:'stun:stun.l.google.com:19302'}].
- Peer setup: const pc = new RTCPeerConnection({iceServers}); pc.addTrack(micTrack, localStream). Use the MDN perfect-negotiation handlers verbatim (makingOffer, ignoreOffer, isSettingRemoteAnswerPending, setLocalDescription() with no args) with polite = myId < peerId. WS messages: {t:'rtc', to, from, description|candidate}. pc.onconnectionstatechange: if 'failed', call pc.restartIce(). Before the TTL expires, call pc.setConfiguration({...pc.getConfiguration(), iceServers: fresh}).
- In ontrack use the track, not event.streams[0] (streams can be empty): pc.ontrack = ({track}) => { if (track.kind === 'audio') attachVoice(peerId, track); }.
- Chrome keep-alive pattern (crbug 40094084): const stream = new MediaStream([track]); const keep = new Audio(); keep.muted = true; keep.srcObject = stream; keep.play().catch(() => {}); const src = ctx.createMediaStreamSource(stream); Keep keep, src and all nodes in voices.set(peerId, {...}) so they aren't garbage-collected (GC causes silence). Use muted, not volume=0 (Safari/iOS ignore volume). It's harmless in Firefox, so apply it to every browser. On leave: disconnect every node, then keep.pause(); keep.srcObject = null; voices.delete(peerId).
- Per-voice graph: src -> new BiquadFilterNode(ctx,{type:'lowpass',frequency:20000,Q:0.707}) -> new GainNode(ctx,{gain:1}) [occlusion] -> new PannerNode(ctx,{panningModel:'HRTF',distanceModel:'linear',refDistance:1.5,maxDistance:22,rolloffFactor:1}) -> new GainNode(ctx) [alive/dead/user volume] -> voiceBus -> new DynamicsCompressorNode(ctx,{threshold:-18,ratio:4}) -> ctx.destination. Fan the occlusion GainNode out to a reverb-send GainNode (0.1-0.3) feeding a SHARED ConvolverNode. Fan src out to a radio-gate GainNode (gain 0) feeding the shared radio chain. Use equalpower panning for bulk SFX and keep HRTF for 8 or fewer voices.
- three.js variant: THREE.AudioContext.setContext(ctx) before new THREE.AudioListener(). Then const v = new THREE.PositionalAudio(listener); v.setMediaStreamSource(stream); v.setFilters([lowpass, occlGain]); v.setDistanceModel('linear'); v.setRefDistance(1.5); v.setMaxDistance(22); v.setRolloffFactor(1); avatarHead.add(v). The muted keep-alive element is still required. three.js updates panner and listener positions in updateMatrixWorld and already handles Firefox's missing AudioListener.positionX.
- Manual listener update (when not using three.js): const t = ctx.currentTime, L = ctx.listener; if (L.positionX) { L.positionX.setTargetAtTime(x,t,0.03); ...; L.forwardX.setTargetAtTime(fx,t,0.03); ...; L.upY.setTargetAtTime(1,t,0.03); } else { L.setPosition(x,y,z); L.setOrientation(fx,fy,fz,ux,uy,uz); } // Firefox. Panner: pan.positionX.setTargetAtTime(px,t,0.03), etc. Use the same interpolated positions the avatars are drawn with.
- Occlusion: on the listener's client, count walls on a DDA/Bresenham line over the procedural tile grid from listener head to speaker head, treating closed doors as walls. Map 0 walls -> 20000 Hz / gain 1, 1 -> 1500 Hz / 0.55, 2 -> 700 Hz / 0.3, 3+ -> 400 Hz / 0.15. Apply with cancelScheduledValues(t) then setTargetAtTime(v, t, 0.08) at 10-20 Hz; never set .value every frame. Optional: BFS path distance through open doors for 'sound around corners' attenuation.
- Generated impulse response: function makeIR(ctx, sec=2.0, decay=2.5){ const n=Math.floor(ctx.sampleRate*sec), b=ctx.createBuffer(2,n,ctx.sampleRate); for(let c=0;c<2;c++){ const d=b.getChannelData(c); for(let i=0;i<n;i++) d[i]=(Math.random()*2-1)*Math.pow(1-i/n,decay); } return b; } Make one ConvolverNode per room type (small 0.6 s, hall 2.2 s, cave 3.5 s; normalize defaults to true) and crossfade the send gains when the listener changes room.
- Radio chain (shared, 2D): hp = BiquadFilter highpass 400 Hz -> lp = lowpass 2800 Hz -> WaveShaperNode {curve: k=30 soft-clip curve ((1+k)*x/(1+k*|x|)), oversample:'4x'} -> DynamicsCompressor {threshold:-30, ratio:8, attack:0.003, release:0.1} -> radioBus. Add a looped 2 s white-noise AudioBuffer through a 1.5 kHz bandpass at gain 0.02 while any transmission is active. Squelch: on key down and up, play 120 ms of noise ramping 0 -> 0.3 in 5 ms and back to 0 in 40 ms. Only route a speaker into the radio when they transmit (WS {t:'radio', on}) and the local player holds a powered walkie.
- Mic capture: getUserMedia({audio:{deviceId: id ? {exact:id} : undefined, echoCancellation: !headphonesMode, noiseSuppression:true, autoGainControl:true, channelCount:1}}). It requires HTTPS (a tunnel URL or localhost); a plain http://100.x Tailscale IP is not a secure context. Never connect the local mic to ctx.destination. Leave the AudioContext output on the default device: Chrome-wide AEC cancels per output device, and setSinkId is Chrome-only.
- Mic-tap AudioWorklet (served same-origin, ctx.audioWorklet.addModule('/worklets/mic-tap.js')): in process(), accumulate the sum of squares and write samples into a ring Float32Array(sampleRate*6). Every 960 frames postMessage({rms}). On 'snap' messages, copy the last N samples out and transfer the buffer. Connect micSrc -> tapNode -> GainNode(0) -> destination so it is always pulled. Main thread: db = 20*log10(rms+1e-9), open at -45 dBFS, close at -52 dBFS after 250 ms hangover. Calibrate with a mic test in character creation, since AGC normalizes levels.
- Push-to-talk: micTrack.enabled = keyHeld affects all senders and sends silence. Don't toggle enabled for voice-activation gating, because it clips word onsets; gate monster noise events instead, or use a send-side gain with pre-roll. Dead gating: for each alive peer, await sender.replaceTrack(iAmDead ? null : micTrack); restore on revive or a new round.
- Bitrate and debug stats: const s = pc.getSenders().find(x => x.track?.kind === 'audio'); const p = s.getParameters(); if (!p.encodings?.length) p.encodings = [{}]; p.encodings[0].maxBitrate = 32000; await s.setParameters(p). Relay badge: in getStats find the 'transport' report's selectedCandidatePairId, then the remote candidate's candidateType ('relay' means TURN). Firefox: use the candidate-pair report with selected === true. Watch inbound-rtp audioLevel, concealedSamples and jitterBufferDelay. Debug pages: chrome://webrtc-internals, about:webrtc.
- Mimic clip format: on a voice-detection close event (segment 0.8-3.5 s), take the ring snapshot including 250 ms pre-roll, downsample 48 kHz to 24 kHz (average pairs), convert to Int16, and ws.send(binary [u8 type=0x10][u8 playerIdx][u32 sampleRate][Int16 PCM]). Host keeps it in memory only. Playback: buf = ctx.createBuffer(1, n, 24000); copyToChannel(Float32 from Int16 / 32768); new AudioBufferSourceNode(ctx, {buffer: buf, playbackRate: 0.96}) -> the same lowpass/occlusion/panner chain positioned at the monster.
- WebCodecs fallback (later): enc = new AudioEncoder({output: (chunk) => { const b = new Uint8Array(chunk.byteLength); chunk.copyTo(b); ws.send(pack(seq++, chunk.timestamp, b)); }, error: console.error}); cfg = {codec:'opus', sampleRate: ctx.sampleRate, numberOfChannels:1, bitrate:24000, opus:{application:'voip', signal:'voice', frameDuration:20000, useinbandfec:true, usedtx:true}}; check (await AudioEncoder.isConfigSupported(cfg)).supported, then enc.encode(new AudioData({format:'f32-planar', sampleRate: ctx.sampleRate, numberOfFrames: frame.length, numberOfChannels:1, timestamp: us, data: frame})). Receiver: dec.configure({codec:'opus', sampleRate:48000, numberOfChannels:1}); dec.decode(new EncodedAudioChunk({type:'key', timestamp, data})); in the output callback, ad.copyTo(f32, {planeIndex:0, format:'f32-planar'}); ad.close(); post to a playout AudioWorklet with a 60-100 ms jitter buffer that drops audio beyond 200 ms. The server only forwards to peers without a P2P link.
- LiveKit plan B: server: const at = new AccessToken(LK_API_KEY, LK_API_SECRET, {identity: playerId}); at.addGrant({roomJoin:true, room: lobbyId}); const jwt = await at.toJwt(). Client: const room = new Room({webAudioMix:{audioContext: ctx}}); room.on(RoomEvent.TrackSubscribed, (track, pub, participant) => { if (track.kind === 'audio') { track.setWebAudioPlugins([lowpass, occlGain, panner]); track.attach(); } }); await room.connect(LK_URL, jwt). Plugin nodes must not be pre-connected; the SDK chains them in array order.
- Playwright test sketch: const browser = await chromium.launch({channel:'chrome', args:['--use-fake-ui-for-media-stream','--use-fake-device-for-media-stream','--use-file-for-fake-audio-capture=C:/abs/voice.wav%noloop','--autoplay-policy=no-user-gesture-required']}). Open 2-4 pages on the tunnel or localhost URL, join the same lobby, and from page.evaluate read window.__voiceDebug (bytesReceived, analyser RMS per peer). Assert RMS > 0.01 within 5 s. Without a file, the fake device plays a beep, which is enough for level assertions.
- Bandwidth and TURN budget: Opus ~32 kbps plus ~23 kbps headers at 50 pps is about 55 kbps per stream. 8 players means about 385 kbps up and down per client. One relayed pair for 3 h is about 150 MB of TURN egress, compared with 1,000 GB free per month.

## Key facts
- (high) Chromium issue 40094084 (old crbug 933677), 'MediaStream from RTC is silent (in WebAudio, MediaRecorder, etc.) if not attached to a media element', is still open: status Assigned, P2, created 2019-02-20, last modified 2026-06-11. Decoded from the tracker JSON; the status code was checked against known Duplicate (10) and Fixed (4) issues. [https://issues.chromium.org/issues/40094084]
- (high) Several later reports are closed as duplicates of 40094084: 40637961 ('Web Audio sink is insufficient for a remote WebRTC PeerConnection to output audio frames', 2019), 40224931 ('WebRTC audio streams don't work with WebAudio', 2022) and 40071445 ('Gain remote audio stream with Web Audio does not works', 2023). [https://issues.chromium.org/issues/40224931]
- (medium) Chromium issue 40504498 (old 687574), 'AEC when using Web Audio API', is marked Fixed (last change 2024-03-11). This fits Chrome-wide AEC now covering Web Audio output. [https://issues.chromium.org/issues/40504498]
- (high) In Chromium main, kChromeWideEchoCancellation is FEATURE_ENABLED_BY_DEFAULT and is compiled in for is_win || is_mac || is_linux. The code comment reads: 'mix and cancel all audio playback going to a specific output device in the audio service'. [https://chromium.googlesource.com/chromium/src/+/refs/heads/main/media/base/media_switches.cc]
- (high) How Chromium picks the echo canceller: echoCancellation:true (browser decides) uses ChromeWide, unless system AEC is enforced (flag off by default) or loopback AEC is forced on (param false by default). 'remote-only' uses the PeerConnection canceller. 'all' uses the loopback-based canceller (system loopback as AEC reference, Win/Mac, enabled by default), which also cancels other apps' audio. [https://chromium.googlesource.com/chromium/src/+/refs/heads/main/third_party/blink/renderer/platform/mediastream/media_stream_audio_processor_options.cc]
- (high) Chrome 141 extended the getUserMedia echoCancellation constraint to accept 'all' and 'remote-only' in addition to true/false. The runtime flag GetUserMediaEchoCancellationModes is 'stable'. [https://developer.chrome.com/release-notes/141]
- (low) Chrome-wide AEC has been the default 'in most cases' since about Chrome 106 (per a 2022 bug report). Zoom's SDK assumes it on Chrome/Edge 111+ (Win/Mac/Linux). A Zoom devforum post (2026-08-04) reports audio leaking into the mic on Edge/Windows but not on Chrome. That is inference from behavior, not verified. [https://devforum.zoom.us/t/issupportchromewideaec-sniffs-browser-name-version-breaking-echo-cancellation-on-microsoft-edge/145288]
- (medium) In Firefox, the AEC reference is the mixed output of the MediaTrackGraph (MediaTrackGraphImpl::NotifyOutputData -> AudioProcessingTrack -> AnalyzeReverseStream). Web Audio output in the same graph (same window and rate) is therefore cancelled. Audio from other tabs may not be. [https://github.com/mozilla-firefox/firefox/blob/main/dom/media/MediaTrackGraph.cpp]
- (high) Firefox 148 fixed bug 1674892, 'Enable connecting getUserMedia and MediaStreamAudioSourceNode running at different rates'. Earlier versions threw NotSupportedError when the AudioContext used a non-default sampleRate. [https://bugzilla.mozilla.org/show_bug.cgi?id=1674892]
- (high) Firefox does not support the AudioListener positionX/forwardX/upX AudioParams, so it must use the deprecated setPosition()/setOrientation(). PannerNode.positionX is supported (Firefox 50+). three.js r186's AudioListener already falls back automatically. [https://github.com/mdn/browser-compat-data/blob/main/api/AudioListener.json]
- (high) Web Audio spec: the 'linear' distance model clamps d to [refDistance, maxDistance] and clamps rolloffFactor to [0,1], so gain reaches 0 at maxDistance when rolloff is 1. 'inverse' (the default) and 'exponential' never reach 0. [https://webaudio.github.io/web-audio-api/#dom-distancemodeltype-linear]
- (high) Cloudflare Realtime SFU and TURN cost $0.05 per GB of egress. The first 1,000 GB each month is free and is shared between SFU and TURN. SFU ingress is free, and TURN-to-SFU traffic is not charged twice. [https://developers.cloudflare.com/realtime/pricing/]
- (high) Cloudflare TURN credential API: POST https://rtc.live.cloudflare.com/v1/turn/keys/$TURN_KEY_ID/credentials/generate-ice-servers with 'Authorization: Bearer $TURN_KEY_API_TOKEN' and body {"ttl":86400}. It returns 201 with iceServers: stun:stun.cloudflare.com:3478 plus turn: 3478/udp, 443/udp, 3478/tcp, 80/tcp and turns: 5349/tcp, 443/tcp. Docs say port 53 is blocked by browsers, so filter it out. Credentials can be revoked via .../credentials/$USERNAME/revoke. [https://developers.cloudflare.com/realtime/turn/generate-credentials/]
- (high) Cloudflare TURN FAQ: credential TTL is at most 48 h (refresh with RTCPeerConnection.setConfiguration()). Relay is UDP only (no RFC 6062 TCP allocations) with IPv4 relay addresses, but clients may reach TURN over TCP/TLS. STUN at stun.cloudflare.com is free and unlimited. Packets may be dropped above 50-100 Mbps or 5-10k pps per client. TURN does not serve the China network. [https://developers.cloudflare.com/realtime/turn/faq/]
- (high) LiveKit Cloud Build (free) plan: 5,000 WebRTC participant-minutes, 100 concurrent participants, 50 GB downstream, 1,000 agent minutes. These allowances are hard caps; new requests fail once exceeded. Ship plan: $50/mo with 150,000 minutes (then $0.0005/min), 1,000 concurrent, 250 GB. [https://docs.livekit.io/home/cloud/quotas-and-limits/]
- (high) Metered TURN free plan is 500 MB/month (ingress + egress) with no credit card. Paid tiers: Growth $99/mo for 150 GB, Business $199/mo for 500 GB. The older Open Relay page still claims 20 GB/month free, which conflicts with this. [https://www.metered.ca/pricing]
- (medium) Cloudflare RealtimeKit (managed SDK, formerly Dyte) lists audio-only participants at $0.0005/min and audio/video at $0.002/min (pricing page updated 2026-09-03). The page doesn't state a free tier or GA status. [https://developers.cloudflare.com/realtime/realtimekit/pricing]
- (high) WebCodecs AudioEncoder, AudioDecoder and AudioData are supported in Chrome 94+, Edge 94+, Firefox 130+ (desktop only, not Android) and Safari 26+. They need a secure context and also work in dedicated workers. [https://github.com/mdn/browser-compat-data/blob/main/api/AudioEncoder.json]
- (high) MediaStreamTrackProcessor is supported in Chrome 94 and Safari 18 but not Firefox. A portable mic-to-WebCodecs path must capture PCM with an AudioWorklet (Chrome 66, Firefox 76, Safari 14.1). [https://github.com/mdn/browser-compat-data/blob/main/api/MediaStreamTrackProcessor.json]
- (high) OpusEncoderConfig members and defaults: format 'opus', signal 'auto', application 'audio' ('voip' and 'lowdelay' also allowed), frameDuration in microseconds (default 20000), complexity (default 5 on mobile, 9 elsewhere), packetlossperc 0, useinbandfec false, usedtx false. The codec string is 'opus'. [https://www.w3.org/TR/webcodecs-opus-codec-registration/]
- (high) WebCodecs spec: 'Conversion from any AudioSampleFormat to f32-planar MUST always be supported' in AudioData.copyTo(). Request format:'f32-planar' to feed Web Audio. [https://w3c.github.io/webcodecs/]
- (high) Safari 18.4 added MediaRecorder output to WebM with Opus. [https://webkit.org/blog/16574/webkit-features-in-safari-18-4/]
- (high) AudioContext.setSinkId is Chrome/Edge 110+ only, with no Firefox or Safari support. RTCRtpReceiver.jitterBufferTarget is Chrome 124+ and Firefox 115+. [https://github.com/mdn/browser-compat-data/blob/main/api/AudioContext.json]

- (medium) Chromium's kWebRtcAllowInputVolumeAdjustment is enabled by default, so with autoGainControl:true Chrome may move the Windows mic input slider. [https://chromium.googlesource.com/chromium/src/+/refs/heads/main/media/webrtc/webrtc_features.cc]
