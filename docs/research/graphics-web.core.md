# graphics-web

## Executive summary
As of 2026-10-06 the best fit for a dark, flashlight-lit co-op horror game in the browser is three.js r186 (npm three@0.186.1, published 2026-09-24). Use WebGPURenderer with TSL and the RenderPipeline post stack. It falls back to WebGL2 automatically, and the official manual still calls the renderer 'experimental'. r186 has a copyable official example for nearly every effect the genre needs:
- flashlights that cast shadows and project a cookie pattern (SpotLight.map, ProjectorLight.colorNode, IESSpotLight)
- raymarched volumetric beams that respect spot and point light shadow maps (VolumeNodeMaterial, webgpu_volume_lighting*)
- AO and GI: GTAO/SSAO, SSGI, VXGI (new in r186, WebGPU only), SSR with denoise, LightProbeGrid baking
- anti-aliasing and upscaling: TRAA, TAAU, FSR1, SMAA, FXAA
- camera effects: bloom, DOF, motion blur, film grain, chromatic aberration, lens flare/anamorphic, 3D LUT
- lighting systems: Clustered/Dynamic lighting, cube-map point shadows, VSM, CSM/SunLight.

The main engine constraint is flashlights. In three.js, spotlights that cast shadows or project a map/colorNode are never batched or clustered. Each one adds a shadow render pass and a per-pixel shading cost, and adding lights or toggling castShadow forces shader recompiles. So allocate a fixed pool of 2/4/6/8 shadowed lights by quality preset and reassign them each frame to the nearest or visible players.

A second hard limit comes from WebGPU itself: by default a shader stage gets 16 sampled textures and 16 samplers. three.js requests the default limits and binds one sampler per texture. So use procedural cookies, pack material maps into fewer textures, and pass requiredLimits read from adapter.limits.

Babylon.js 9.29 comes with the most built in (Havok character controller, PCSS soft shadows, bounce light from spotlights via reflective shadow maps, Frame Graph). But its new volumetric lighting only works with directional lights, and its clustered lights cannot cast shadows or use cookies/IES.

PlayCanvas 2.23 handles many flashlights best out of the box: clustered omni and spot lights with shadow and cookie atlases, and since 2.22 volumetric fog lit by those lights. Against that, its WebGPU support is still labelled Beta, it has no SSGI, SSR or motion blur, and coding agents know it much less well.

WebGPU ships in Chrome/Edge 113+ (Windows, macOS, ChromeOS), Firefox 141+ on Windows, Firefox 145/147+ on Apple Silicon and Safari 26. Linux support is partial, so Windows friends on Chrome, Edge or Firefox are covered. WebGPU and microphone capture both require a secure context, so invite links must be HTTPS.

Realistic target, still to be benchmarked: an RTX 3060/4060 at 1080p, or at 1440p with about 0.75 internal scale plus TAAU, holds 60 fps with 4 shadowed 1024² flashlights, half-res GTAO, quarter-res volumetric beams, bloom, TRAA and grain/vignette/CA/LUT.

For physics use Rapier (@dimforge/rapier3d-compat 0.21.0): character controller, doors on revolute joints, carrying on spring joints, ragdolls from joints. Skip cannon-es (last release 2022).

Recommendation: pin three.js r186, go WebGPU-first with a tested WebGL2 fallback, and build a fixed flashlight-light pool. Tonight's chain: PCF-shadowed cookie flashlights, VolumeNodeMaterial beams, height fog, GTAO on the ambient term, bloom, TRAA, then film grain/vignette/CA/LUT, with Low/Medium/High/Ultra presets and TAAU dynamic resolution. Stretch: SSGI or VXGI flashlight bounce light, LightProbeGrid, SSR and motion blur.

## Recommendations
- [TONIGHT] Engine: three@0.186.1 (pin exact), import * as THREE from 'three/webgpu', TSL from 'three/tsl', addons from 'three/addons/...'; WebGPURenderer WebGPU-first with automatic WebGL2 fallback; Vite 8.3.3 dev server. -- Largest body of LLM/agent knowledge, ~230 official webgpu_* examples to copy verbatim, richest post stack of any web engine, and the only one of the three with shadow-aware volumetric SPOT-light beams in core (VolumeNodeMaterial). Babylon/PlayCanvas advantages (PCSS, clustered shadowed lights) do not outweigh agent velocity tonight.
- [TONIGHT] Fixed flashlight light pool: create at startup N shadow-casting ProjectorLights (Low 2 @512, Med 4 @1024, High 6 @1024, Ultra 8 @2048) + (maxPlayers - N) non-shadow SpotLights; every frame assign the local player's flashlight + nearest/in-frustum remote flashlights to shadowed slots; unused slots intensity 0. Never add/remove lights or toggle castShadow at runtime. -- Shadowed and map/colorNode spotlights bypass DynamicLighting/ClusteredLighting batching; light-set changes rehash lights and recompile pipelines (visible hitches when a player joins or toggles a light). Own-flashlight shadows (monster silhouettes on walls) are the core horror visual.
- [TONIGHT] Flashlight look: ProjectorLight (extends SpotLight) angle ~0.42 rad, penumbra 0.6-0.8, decay 2, distance ~28, PCFShadowMap with shadow.radius 2-4, bias -0.0004, normalBias 0.02, near 0.15/far 28; cookie via TSL colorNode (procedural hot-spot ring + smudge noise) instead of a texture; subtle sway/lag and battery flicker via uniform(). -- colorNode cookies cost no texture/sampler binding (16-per-stage default limit), animate for free, and avoid asset authoring. Copy from webgpu_lights_projector.html and webgpu_lights_spotlight.html; IES variant webgpu_lights_ies_spotlight.html.
- [TONIGHT] Volumetric flashlight beams: copy webgpu_volume_lighting.html - VolumeNodeMaterial box over the active level chunk on layer 10, steps 8-12, offsetNode = bayer16(screenCoordinate), scatteringNode = 3D-noise dust density, separate pass(scene, camera, {depthBuffer:false}) with setLayers + setResolutionScale(0.25), gaussianBlur, added to scene color before TRAA. Only flashlights and 1-2 key lamps get layer 10. -- Shadowed light shafts through dust are the signature Phasmophobia/flashlight look; quarter-res keeps it ~1-2 ms. GodraysNode can't do spot lights and Babylon 9's volumetric task is directional-only.
- [TONIGHT] MVP post chain (RenderPipeline): opaque pre-pass with MRT normals(UnsignedByte)+velocity -> GTAO ao() at resolutionScale 0.5 injected via scenePass.contextNode = builtinAOContext(...) -> + volumetric -> bloom(node, ~0.3, ~0.4, ~0.9) for emissives -> traa() -> film() grain, chromaticAberration() (low), vignette() from tsl/display/CRT.js, lut3D() horror grade; ACES or AgX/Neutral tone mapping; antialias:false. -- All nodes are fragment-based and work on both backends; grain/dither also hides 8-bit banding in dark fog gradients. Pattern taken directly from webgpu_postprocessing_ao.html, _traa, _bloom, _ca, _3dlut, _retro.
- [TONIGHT] Atmosphere: scene.fogNode = fog(color, exponentialHeightFogFactor(density, height)) plus a very low HemisphereLight floor (0.02-0.05) so scenes are never pure black on uncalibrated monitors. -- Cheap depth cue, matches webgpu_fog_height.html; prevents 'can't see anything' complaints from friends.
- [TONIGHT] Materials for procedural levels: MeshStandardNodeMaterial with TSL triplanarTexture() on CC0 PBR sets (albedo + normal + packed ORM), roughness breakup via mx_fractal_noise_float, emissive exit signs/LEDs feeding bloom; merge static geometry per room chunk. -- Triplanar removes the need for UVs on generated geometry; ≤3 textures per material keeps sampler budget for shadow maps.
- [TONIGHT] Quality presets + dynamic resolution: preset auto-pick from a 2-second benchmark; scenePass.setResolutionScale(0.5-1.0) + taau() + sharpen() (webgpu_upscaling_taau.html), adjusted at most once per second from GPU ms (trackTimestamp + resolveTimestampsAsync). -- Friends' GPUs unknown; host has RTX 5090 @4K. Resolution-scale changes reallocate render targets, so step coarsely with hysteresis.
- [TONIGHT] Agent test harness: Playwright 1.63 driving real Chrome on the host GPU, window.__game API (seed, camera pose, step frames, perf), deterministic golden frames + pixelmatch, every test run twice (WebGPU and ?webgl=1 forceWebGL), buffer debug views via Inspector/toInspector. -- No human eyes in the loop; reference-delta screenshot loops are how wolfmayostudio and threejs-punk keep WebGPU visuals and perf under control.
- [TONIGHT] Physics: @dimforge/rapier3d-compat@0.21.0 imported from npm (not three/addons/physics/RapierPhysics.js): KinematicCharacterController for players, revolute joints with limits/motor for doors, kinematic hand + spring joints for carrying (multi-player lifting), spherical+revolute ragdolls on death. -- Only maintained JS physics with a built-in character controller and simple JS API; same package runs in Node 24 for host-authoritative props. cannon-es is stale (2022); Jolt is faster but needs manual memory management and COOP/COEP for threads.
- [later] Stretch: flashlight bounce GI - SSGI (ssgi(), Low preset 1 slice x 12 steps with TRAA) on High; VXGI (vxgi(), 128^3, 2-4 cones, voxelize once after level generation) on Ultra/WebGPU only. -- In a flashlight-lit scene AO only touches the tiny ambient term; bounce light from lit walls is the bigger realism win. VXGI's static-geometry requirement fits once-per-round procedural levels.
- [later] Stretch: LightProbeGrid baked on the GPU right after level generation (grid.bake(renderer, scene, {cubemapSize: 8, bounces: 1})) for static lamp bounce. -- Cheap at runtime, works for static lighting; complements dynamic flashlights.
- [later] Stretch: SSR on wet floors (webgpu_postprocessing_ssr_denoise.html), motion blur (webgpu_postprocessing_motion_blur.html), DOF for death/spectator cam, lens flare/anamorphic on lamps, RectAreaLight fluorescent panels (+ webgpu_volume_lighting_rectarea), 1-2 point-light cube shadows at 128-256^2 with shadow.autoUpdate=false, DynamicLighting/ClusteredLighting for dozens of unshadowed lamps, GPU dust/rain particles (webgpu_compute_particles_rain, webgpu_particles_soft), MeshSSSNodeMaterial monster skin, outline on interactables, HDR output (webgpu_hdr.html) for the host monitor. -- Each is an isolated, copyable example; add once MVP perf is measured. threejs-punk dropped SSR for stability, so keep it High/Ultra-only.
- [later] Stretch: KTX2 textures (KTX2Loader + basis transcoder, UASTC normals / ETC1S albedo) via gltf-transform 4.5.1 or KTX-Software. -- Cuts VRAM/bandwidth for mid-range GPUs, but needs native encoder binaries; WebP/JPEG is fine for tonight.
- [later] Stretch/alt art mode: 'Retro' preset (retroPass, bayerDither, pixelation, posterize, scanlines) at low internal res - Lethal Company/R.E.P.O.-style. -- Makes primitive procedural assets look intentional and rescues weak PCs; trivially switchable in RenderPipeline.
- [later] Do NOT use tonight: Gaussian splats (three/addons/objects/GaussianSplat.js, Spark 2.3.1) for gameplay spaces; switching to Babylon/PlayCanvas; cannon-es. -- Splats are pre-lit and do not respond to flashlights; engine switch loses agent velocity; cannon-es unmaintained.

## Risks
- Shader/pipeline compile hitches when the light set or material permutations change (player joins, flashlight toggled, castShadow flipped) on an 'experimental' renderer. => Fixed light pool sized by preset, toggle via intensity only, instantiate every material/light/post node before await renderer.compileAsync(scene, camera) on the loading screen, and log frame spikes from window.__game.perf() in Playwright runs.
- Exceeding WebGPU's 16 sampled textures / 16 samplers per fragment stage with 6-8 shadowed lights + texture cookies + PBR maps, causing pipeline validation errors (black/invisible meshes). => Procedural colorNode cookies, ≤3 textures per material (packed ORM), cap pool to 6-8, request requiredLimits from adapter.limits with a retry-without fallback, and add an automated 8-light stress scene to the test harness.
- Non-HTTPS invite URL (raw http://LAN or Tailscale IP) leaves navigator.gpu undefined (silent WebGL2 fallback) and blocks microphone capture for proximity voice. => Serve invites only over HTTPS (tunnel or Tailscale HTTPS); show the active backend in the HUD and lobby so a silent fallback is visible.
- Friends with Chrome hardware acceleration disabled, old GPUs or Linux end up on WebGL2/SwiftShader at slideshow frame rates. => 2-second auto-benchmark selects Low/Retro preset; lobby warning with fix instructions (enable hardware acceleration, set Chrome to High performance GPU in Windows Graphics settings); recommend Chrome/Edge over Firefox (Firefox WebGPU had IPC/latency overhead).
- Agents write obsolete three.js APIs (EffectComposer, ShaderMaterial, onBeforeCompile, PostProcessing, setResolution, PCFSoftShadowMap) from older training data. => Vendor r186 example HTML as references, pin three@0.186.1 exactly, and enforce the forbidden-API grep in CI/pre-commit.
- Performance estimates are wrong for mid-range GPUs (4 shadowed flashlights + volumetrics + GTAO + TRAA at 1080p/60). => Benchmark in the first hour with trackTimestamp on the host plus a throttled preset (0.6 scale); dynamic resolution via TAAU; drop volumetric steps/resolution and shadow pool first.
- TRAA/TAAU ghosting or smearing on the fast flashlight sweeps and the monster; volumetric noise shimmer. => Velocity MRT on all moving meshes (including skinned), keep jitter-aware IGN dithering, offer SMAA/FXAA on Low, tune volumetric blur before TRAA.
- Dark scenes crush to black or band heavily on friends' monitors. => Floor ambient 0.02-0.05, exposure slider in settings, AgX/Neutral tone mapping option, film grain/IGN dithering after tone mapping.
- Rapier version churn (0.20 dist/ move, 0.21 signature changes) and the three.js RapierPhysics addon pulling 0.17.3 from Skypack at runtime. => Import @dimforge/rapier3d-compat@0.21.0 from npm on both client and Node server, never use the addon wrapper or CDN imports.
- Babylon/PlayCanvas would handle many shadowed flashlights more efficiently (PlayCanvas clustered shadow+cookie atlases; Babylon PCSS), so three.js may hit a ceiling at 8 players. => Only the nearest/visible 4-6 flashlights cast shadows; remote far flashlights unshadowed; revisit engine choice only if the stress test fails, not tonight.

## Decision-critical claims
- three@0.186.1 (2026-09-24) is the latest three.js, and its WebGPURenderer + RenderPipeline + TSL addons include working examples for every MVP effect (shadowed cookie spotlights, VolumeNodeMaterial volumetric spot beams, GTAO, TRAA, TAAU, bloom, film, CA, LUT, height fog). These run on both the WebGPU and WebGL2 backends; VXGI and ClusteredLighting need WebGPU.
- In three.js r186, shadow-casting spotlights and spotlights with map/colorNode are never batched (DynamicLighting) or clustered (ClusteredLighting is non-shadow point lights only), and changing the light set or castShadow recompiles. A fixed, preset-sized flashlight light pool is therefore mandatory.
- WebGPU default limits are 16 sampled textures and 16 samplers per shader stage, and three.js requests default limits unless requiredLimits is passed, with one sampler per texture uniform. This caps shadow maps + cookies + material maps per material; the exact cap on friends' Chrome/D3D12 adapters is unverified.
- WebGPU (and getUserMedia for voice) requires a secure context, so invite links must be HTTPS or friends silently get the WebGL2 fallback and no microphone.
- Windows friends on Chrome/Edge 113+ or Firefox 141+ have WebGPU. Firefox on Linux or Intel Macs, and most Linux Chrome setups, do not, per the gpuweb wiki updated 2026-10-02.
- Babylon 9's new volumetric lighting is directional-only and three.js GodraysNode excludes spot lights, so VolumeNodeMaterial (three.js) or PlayCanvas 2.22+ clustered volumetric fog are the only built-in paths to shadowed flashlight beams.
- Estimated (not measured): RTX 3060/4060 sustains 1080p60 with 4 shadowed 1024² flashlights + quarter-res volumetrics + half-res GTAO + bloom + TRAA, at roughly 9-13 ms GPU.
- @dimforge/rapier3d-compat 0.21.0 provides a kinematic character controller plus revolute, spherical, spring and rope joints, and runs in both browser and Node 24, which covers carrying, doors and ragdolls.

## Open questions
- The WebSearch budget for this run ran out partway through research. Everything after that was verified by fetching primary sources directly (GitHub raw/API, npm registry, unpkg package contents, MDN, W3C, vendor docs). No independent mid-range GPU benchmarks for three.js r186 shadow/volumetric costs were found, so the frame-time budgets are engineering estimates.
- What do adapter.limits (maxSamplersPerShaderStage, maxSampledTexturesPerShaderStage, maxColorAttachmentBytesPerSample) report on the host RTX 5090 and on each friend's Chrome/D3D12 adapter? This sets how many shadowed + cookie flashlights one material can see. Check webgpureport.org or log it in the lobby.
- Which GPUs and browsers do the friends use, and is Chrome hardware acceleration enabled? This decides the default preset and whether the WebGL2 path needs polish tonight.
- Art direction: photoreal-dark (volumetrics, GI) or a Lethal Company/R.E.P.O.-style low-res stylized look (Retro preset)? This changes the effect priority list and asset needs.
- Max players per lobby (4 vs 8)? It sizes the shadowed flashlight pool and volumetric cost.
- Asset sourcing for PBR textures, props and characters (CC0 libraries, procedural) is outside this topic but gates perceived graphics quality more than any post effect.
- Does three.js r186 ClusteredLighting run at all on the WebGL2 fallback, or only on WebGPU? It is compute- and storage-buffer-based, so assume WebGPU only and use DynamicLighting cross-backend.
- Does headless Chrome (--headless=new) on this Windows host expose the RTX 5090 to WebGPU, or must agent screenshot runs be headed? Verify once with navigator.gpu.requestAdapter() in Playwright.
