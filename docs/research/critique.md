# Critique

## Consolidated stack
DRAFT TONIGHT STACK (critic consolidation):
1 PLATFORM: browser game. three@0.186.1 (pinned) WebGPURenderer with automatic WebGL2 fallback, TSL and RenderPipeline. Vite 8.3.3, TypeScript, npm workspaces: apps/client, apps/server, packages/shared (protocol, constants, procgen, nav), tools/, tests/. Why: all 10 topics agree it is the only path that gets invite-by-link, proximity voice, server-side LLM and agent testability within hours. Godot web is WebGL2-only, and Unity/Unreal take days to set up.
2 SERVER/NETCODE: one Node 24 process on 127.0.0.1:3000 serving dist plus ws 8.22.0 + msgpackr 2.1.0.
   - 30 Hz fixed step on a performance.now accumulator woken by setTimeout(1); setInterval measured 21 Hz on this host.
   - 20 Hz snapshots.
   - Client-authoritative poses, validated against the grid; the server owns monsters, items, objectives, economy and AI.
   - Resume tokens; ws.ping every 20 s (idle sockets measured closing at 125.7 s).
   - Crew code in the URL hash, never in the WebSocket URL.
   Why: simple, fully debuggable, and keys stay on the host.
3 INVITES: cloudflared 2026.10.0 portable exe running a quick tunnel (no account, HTTPS, WebSockets verified, about 20 ms p50). Start it once and never restart it. Build the link from GET 127.0.0.1:20241/quicktunnel. Tailscale Funnel is the backup. Why: WebGPU and the mic both need a secure context.
4 LEVELS: procgen's tested lattice+BSP+zones generator (xmur3+sfc32, 1 m edge grid), retuned to 12-24 rooms with speakable callsigns. The server generates and broadcasts the layout JSON. Edge-grid A*, line of sight and the Dijkstra sound flood drive both AI and collision; adjacency culling handles visibility. Why: 1.6 ms generation, 1000/1000 seeds valid, and no cross-engine determinism risk.
5 GRAPHICS:
   - Fixed shadowed flashlight pool: ProjectorLight, PCF, procedural colorNode cookie. Presets Low 2@512, Med 4@1024, High 6, Ultra 8@2048.
   - Quarter-res VolumeNodeMaterial beams, half-res GTAO, bloom, TRAA with TAAU dynamic resolution, film/CA/vignette/LUT, height fog plus an ambient floor.
   - Fixtures from a fixed pool of 16-32 unshadowed point lights under DynamicLighting.
   - compileAsync behind the loading screen; preset picked by a 2 s benchmark.
   - WebP + meshopt assets: 1K props, 2K surfaces, 100 MB or less on first load.
   Why: delivers the signature flashlight horror look while respecting the 16-sampler limit and recompile hazards, and survives the WebGL2 fallback.
6 COLLISION: capsule-vs-edge-grid on client and server, kinematic doors, attached carries. Rapier later.
7 ASSETS: fetch-assets.mjs driven by a JSON manifest.
   - Poly Haven + ambientCG CC0 props, surfaces and dark HDRIs; doors, lockers and gurneys built procedurally.
   - Quaternius UAL2 mannequins, plus UAL1 v3 from itch.io for locomotion (one user click, or Playwright).
   - Audio: Kenney and OpenGameArt CC0, Little Robot CC-BY (credited), and procedural Web Audio for drone, heartbeat, fluorescent hum and radio.
   - credits.json generated alongside.
8 CHARACTER CREATOR: faceless suit on the mannequin rig (male/female), colour slots, bone-scale sliders, helmet with emissive CanvasTexture visor glyphs, accessories. The profile JSON travels in Hello and is stored by player token.
9 VOICE: WebRTC P2P mesh, audio only, capped at 6 players, using perfect negotiation over the game WebSocket.
   - Cloudflare Realtime TURN credentials minted on the server.
   - A muted <audio> keep-alive per remote stream (verified required on Chrome 154).
   - Audio graph: occlusion lowpass and gain, then an HRTF panner for direction, then a path-distance loudness gain.
   - Radio chain plus walkie leak; a dead channel via replaceTrack(null).
   - echoCancellation:true plus headphones; a connection badge per peer.
10 VOICE AS GAMEPLAY: an AudioWorklet mic tap produces a calibrated band (whisper 3 m, talk 10 m, shout 25 m, scream 35 m) carried in each pose packet. The server floods that sound through the room graph, and the same radius decides who hears it, teammates and monsters alike (the 1:1 rule).
11 STT: a host Python 3.13 sidecar on 127.0.0.1 running faster-whisper 1.2.1 + ctranslate2 4.8.2, large-v3-turbo fp16 on CUDA. Pin av==16.1.0, fix the language, and use callsigns and player names as hotwords. Parakeet-TDT v3 int8 on CPU is the fallback. Clients upload VAD-gated segments of their own mic over the WebSocket, behind an opt-in consent screen. No dependency on Web Speech.
12 LLM: a server-only AiGateway on @anthropic-ai/sdk 0.131.0 (messages.parse + zodOutputFormat) with AI_MODE mock/record/replay/live, a per-session dollar cap, a spend limit on a dedicated workspace, and circuit breakers. Routes:
   - Listener intent: an enum action plus room/player ids, validated against what was actually overheard. Runs on claude-haiku-4-5 or claude-sonnet-5-5 with thinking {type:'between_tools'}, chosen by measured p95. 2.5 s timeout, maxRetries 0, at most one call per 3 s, with a keyword/rule fallback brain.
   - JEV (probably TypeSafe Jev): an optional sub-second picker for the same enum choice and for biasing the director, enabled only after a consented health check passes.
   - Shift review: claude-sonnet-5-5 at effort low; a template shows at 12 s.
   - Briefing and lore: claude-opus-5-5 at effort low, streamed in the background, with every secret owned by code.
   - Safety: a PG-13 tone guide, no fields named 'reasoning', and refusals fall back to Haiku, then to a template.
13 GAME: DEAD AIR.
   - Loop: van lobby, then a seeded facility. Salvage, twin levers and a 2-carrier Core, then extract before 04:00 (15 real minutes). Shop, then a 3-contract shift quota, ending in a termination letter if missed. Career XP levels 1-7.
   - Monsters: the Listener (LLM picks intent, a rules-driven body executes it, it speaks only through radios), the Hound (hunts by sound) and the Mannequin (moves only when unobserved).
   - A deterministic Left 4 Dead-style director; all balance numbers in JSON config.
14 TESTING AND TOOLING:
   - Playwright 1.63 headless with channel:'chrome' (hardware WebGPU verified on the RTX 5090).
   - One browser per simulated player, each with its own fake-mic WAV.
   - A window.__game test API, golden screenshots with pixelmatch, and ws bots.
   - A forbidden-API grep in CI: EffectComposer, ShaderMaterial, PCFSoftShadowMap, temperature, budget_tokens, thinking disabled.
   - MCPs: chrome-devtools-mcp 1.10.1 (--isolated --headless --no-usage-statistics --no-performance-crux) and Context7. Run claude update; install a portable ffmpeg.
CUT ORDER IF LATE: CCTV feeds, then mimic replay, then LLM lore/briefing, then the Mannequin, then creator extras, then the LLM review (template only), then the Listener's LLM brain (keyword brain only).
ASK THE USER NOW: the Cloudflare TURN key; a dedicated Anthropic workspace with a spend limit; where JEV comes from, plus consent for one health check; player count, browsers, language and headphones; transcription and mimic consent; one itch.io download click; an optional Freesound key.

Move the spirit box to post-MVP, or ship it as one optional radio-scanner gadget. Asset mapping: Mannequin = the UAL mannequin mesh; Listener = an elongated mannequin using bone scale and the Zombie_* clips; the Hound model is still open.

- [game-design vs ai-llm (Haiku 4.5 lifecycle)] game-design says to avoid Haiku 4.5 because its 'retirement window opens 2026-10-15'. ai-llm makes it the primary real-time and fallback model. => Critic spot-check of platform.claude.com model-deprecations: claude-haiku-4-5-20251001 is Active, and 'Not sooner than October 15, 2026' is a tentative floor, not a deprecation notice. - [voice vs assets-audio + tooling-mcp (does Chrome cancel echo from Web Audio playback?)] voice says Chrome-wide AEC, on by default on Windows/Mac/Linux, cancels everything Chrome plays, including voices rendered through Web Audio. assets-audio and tooling-mcp say Chrome does not apply echo cancellation to Web Audio playback; that claim comes from unverified third-party docs. => Critic spot-check: Chromium main media_switches.cc contains BASE_FEATURE(kChromeWideEchoCancellation, base::FEATURE_ENABLED_BY_DEFAULT) inside BUILDFLAG(CHROME_WIDE_ECHO_CANCELLATION), commented 'mix and cancel all audio playback going to a specific output device in the audio service'. The voice topic is likely right for Chrome desktop; Edge and Firefox remain uncertain. Use echoCancellation:true, never 'remote-only'. Strongly recommend headphones, which HRTF needs anyway. Confirm with one real test on speakers.
- [voice vs game-design vs netcode vs procgen vs speech (how voice loudness reaches monsters)] The topics use different pipelines and mappings:
- voice: AudioWorklet gate (open -45 dBFS, close -52 dBFS), WS {t:'voice', db} at 10 Hz, server radius 4-18 m.
- game-design: AnalyserNode bands (whisper 3 m, talk 10 m, shout 25 m, scream 35 m), lobby calibration, sends on change.
- netcode: a 1-byte voiceLevel in each 20 Hz pose.
- procgen: voice radius 4-16 m.
- speech: AnalyserNode every 100 ms at -45 dBFS.
None of them accounts for autoGainControl:true compressing whisper versus shout. => Put one constants module in packages/shared and use a single path: AudioWorklet tap (keeps running in background tabs), then a calibrated band using game-design's table, then a 1-byte level in each pose packet, then a server Dijkstra sound flood over the room graph. The same radius decides both whether teammates hear you and whether monsters do. Verify how much AGC compresses the bands and calibrate per player.
- [voice vs game-design vs assets-audio/tooling-mcp (spatial attenuation model)] voice uses an HRTF PannerNode with distanceModel 'linear', refDistance 1.5, maxDistance 20-25, plus lowpass occlusion from grid wall counts. game-design makes audibility a per-speaker loudness radius measured as room-graph path distance, with clients muting beyond it and radio audio leaking at 0.6x radius around the receiving walkie. assets-audio and tooling-mcp use 'inverse' or 'exponential'. => Use the PannerNode for direction only (linear with a fixed max, or rolloff 0). Add a separate GainNode driven by path distance versus the speaker's current radius, as computed by the server, plus the occlusion lowpass. Keep 'inverse' for SFX only. When A transmits by radio and B holds a walkie, also play A's mesh stream through a panner at B's walkie so bystanders and the Listener overhear it.

Give each room a callsign stencil that also feeds the STT hotwords and the LLM.

## Biggest risks for tonight
- Scope overrun. Roughly 12 subsystems have to fit into a few agent-hours. Unless shared contracts (protocol, layout JSON, loudness constants, test API) are frozen in hour 0 and there is a 'playable with LLM off' checkpoint, integration will break late in the evening.
- Proximity voice can only be fully tested with real remote peers. Known failure modes: Web Audio goes silent without the muted keep-alive element; ICE fails without TURN, which depends on the user creating a key; echo on speakers, worst on Edge; AGC distorting the loudness bands. Mitigation: a remote smoke test before friends join, plus a fallback to a plain <audio> element per peer.
- Real-time AI latency and availability:
- Opus 5.5 cannot turn thinking off.
- The Listener needs decisions in 1-2 s from a host that is probably in the EU.
- JEV's identity is unconfirmed.
Mitigation: measure Haiku 4.5 against Sonnet 5.5 with between_tools; 2.5 s timeouts; a rule-based brain; AI_MODE=mock so the game ships without any LLM.
- Variance in friends' hardware and browsers:
- The WebGL2 fallback lacks ClusteredLighting and VXGI.
- WebGPU limits each shader stage to 16 samplers.
- Shaders recompile when a player joins or the light set changes.
- Mid-range performance is unmeasured.
- A non-HTTPS URL silently drops both WebGPU and the microphone.
- Asset and animation gaps. Basic locomotion and crouch exist only in UAL1, which needs either the itch.io browser flow or retargeting from the DEF rig. There is no Hound model, and Poly Haven has no doors or lockers. The first load comes through a tunnel that does no caching, on an uplink nobody has measured.
- Quick-tunnel fragility:
- It runs a single connection.
- The URL changes if cloudflared restarts.
- Idle connections are cut at 125 s.
- In-flight requests are capped at 200.
- Latency spikes of 1-2 minutes (75-400 ms) were observed.
The netcode must tolerate jitter above 250 ms, and nobody should restart cloudflared mid-session.
- The host PC is a single point of failure. It runs the game at 4K plus the Node server, Whisper on the GPU, Kokoro on the CPU and the tunnel. A crash, sleep or redeploy loses mission state, and contention between these processes has not been tested.
- Privacy, cost and abuse:
- Always-on transcription goes to the host and to Anthropic, and mimic clips record friends' voices.
- The trycloudflare URL is public and can trigger paid LLM calls.
- Keys could leak into the client bundle.
Mitigation: a consent screen, the crew code, a per-session dollar cap, and a bundle grep for 'sk-ant' and 'apikey_'.
- Agents writing from stale API knowledge:
- three.js: EffectComposer, ShaderMaterial, PostProcessing, setResolution, PCFSoftShadowMap, RGBELoader.
- Claude API (each returns 400 on Opus/Sonnet 5.5): temperature, budget_tokens, thinking disabled, assistant prefill, forced tool_choice.
